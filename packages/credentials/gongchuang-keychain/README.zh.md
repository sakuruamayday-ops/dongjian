# @gongchuang/credentials-keychain

[English](README.md) | 中文

## 概述

共创企业助手私有凭据提供器。继承的进程环境变量是只读最高优先级层；用户填写的模型与 MCP 密钥存入 macOS 钥匙串或 Windows 凭据管理器。

<a id="behavior"></a>
## 行为

该提供器明确忽略项目与用户 `.env` 文件，因此打开企业目录不会向已签名桌面产品注入凭据。

记录接口仅开放 `client-connection/browser-session`，供选择持久化认证 loopback 浏览器 cookie 的组合使用。模型、连接器、账号及 OAuth 记录仍全部禁用。随附 Electron 组合采用进程级浏览器会话密钥，因此 Connection 不会读写这条记录；既有 `GONGCHUANG_INTERNAL_BROWSER_SESSION` 条目可以保留但不再使用。引用凭据继续使用受操作系统保护的后端。

其他组合显式选择持久浏览器会话时，macOS 钥匙串临时拒绝会把这项可再生记录视为缺失，使 BrowserAuth 能够轮换它。该降级会使旧 loopback cookie 失效，但不会读取、删除或覆盖用户填写的模型、MCP 或账号凭据；永久存储损坏及替换写入失败仍会关闭失败。

打包后的 macOS 客户端通过固定签名字节的原生 broker 读写 `cn.gongchuang.enterprise-assistant.credentials.v2` 钥匙串服务。客户端主程序在更新中重新签名不会改变 broker 的代码身份；新写入的凭据不再进入 Electron `safeStorage` 密文文件。broker 只接受同 Bundle ID、签名有效且从同一 App 包路径启动它的父进程，请求和密钥只经过标准输入输出管道。

首次从旧版升级时，提供器以一个共享迁移任务顺序解密 `credentials.secure.v1.json` 的完整快照，再逐项写入 broker。macOS 可能要求用户授权旧 `safeStorage` 项目；拒绝、超时或迁移不完整都会关闭失败，用户主动重试会重新执行迁移。旧密文保留用于更新失败后的旧版回滚；`credentials.keychain.v2.json` 串行记录已迁移或已删除的引用，防止并发更新互相覆盖，也防止钥匙串条目异常丢失后回退到过期密文。显式删除先记录逻辑删除，再清理 broker 条目和对应旧密文，因此部分清理失败不会使旧凭据恢复可读。

引用暂时不可读时，解析和状态查询都会返回失败，不会被报告为密钥不存在。消费方保留已存状态并显示重试入口。同一事件循环轮次内检查的引用共享一次钥匙串暂时不可用结果，之后的用户主动重试会重新访问原生凭据库。只有前述可恢复的内部浏览器会话记录采用独立的缺失回退。

操作系统凭据库能够消除明文文件和环境变量暴露，但它不是抵御同一已登录操作系统用户下任意程序的安全边界。产品不把签名 Python 运行时加入普通任务命令搜索路径，也不随运行时提供包安装器；但获准运行的同用户进程工具仍拥有该操作系统用户自身的权限。本包在其他组合中不承诺进程隔离。

Windows 端在每个提供器生命周期内只启动一个隐藏 PowerShell 宿主，并只加载一次凭据管理器适配器。凭据请求通过 UTF-8 标准输入串行传递，密钥不进入命令行参数；提供器释放时会等待会话关闭，失效或返回异常的会话会先丢弃，后续请求再启动新宿主。

<a id="dev-note"></a>
## 开发备注

签名桌面 Host 持有该提供器的生命周期，并只向消费方提供凭据引用，不向渲染器暴露密钥值。

## 运行时不变式

不发布运行时不变式伴随入口，因为凭据服务定义已经持有更新事件关系，平台命令则由包级测试覆盖。

<a id="model-experience"></a>
## 模型体验

### 已配置模型提供方与连接器的凭据解析

#### 模型看到的内容

没有直接内容。本包只决定获准的 Host 适配器能否解析 `DEEPSEEK_API_KEY` 等凭据引用并向其消费方提供服务。

#### Token 影响

直接影响为零。凭据解析成功后出现的提示词、工具 schema 或结果由相应模型提供方或连接器消费方持有。

#### KV Cache 影响

本包不改变请求内容。凭据变化可能使所属模型提供方或连接器重新构建自己的模型可见内容。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- Linux 不是受支持的桌面发布平台并会关闭失败。
- 如果组合向模型开放同用户进程执行，模型仍可能调用平台凭据 API；该组合必须另行增加进程策略，不能只依赖本存储后端。
- 正式设备验收须让目标 macOS 包真实完成旧凭据迁移、通过界面投影账号与模型状态并由固定 broker 逐项读回；仅证明旧密文文件未变化不算通过。Windows 仍须验收凭据管理器的读、写、删除行为。
