# @gongchuang/model-connections

[English](README.md) | 中文

## 概述

提供方配置将凭据读取包含在同一次异常处理内。即使后续凭据诊断也失败，提供方仍会从 `checking` 收尾为可见的暂时错误；此恢复不替换已有密钥。

共创企业助手的宿主侧模型配置服务。客户端展示 34 个已确认提供方与一个本地／自定义端点。一份注册表统一管理 Host 与渲染端的名称、固定地址、协议和凭据字段；模型能力仍由适配器拥有，不能根据模型名称猜测。迁移时复用已有凭据；移除的入口不展示，但不会删除其系统凭据。

<a id="behavior"></a>
## 行为

密钥仅被保存不代表连接完成。提供模型目录的服务先完成认证探测，再把密钥写入操作系统凭据库；不提供模型目录的服务要求用户填写模型 ID。本机端点可以不填密钥。渲染器快照包含状态、模型标识和已保存的可编辑端点字段，不含密钥或凭据引用。重新打开或重启后，表单恢复已存显示名称、验证后的基础地址、协议和模型 ID；API Key 输入框保持为空。

Anthropic 兼容目录以 API 根地址为基准使用 `/v1/models`，保留 `/anthropic` 等网关前缀。以 `sk-kimi-` 开头的 Kimi 订阅密钥使用 `https://api.kimi.com/coding/v1`；普通 Kimi 密钥使用所选 Moonshot 区域。配置和恢复从已存密钥解析同一端点。

已保存凭据在桌面主界面挂载后再恢复。macOS 钥匙串响应较慢或暂时不可用时，只会延迟对应提供方的连接状态，不会延迟主窗口和本地普通会话。用户主动配置或刷新仍会排在该提供方的后台恢复任务之后串行执行；一个提供方失败不会清空其他提供方的健康目录。

钥匙串暂时读取失败属于可重试的连接错误，不等同于 API Key 缺失或无效。刷新会再次读取既有引用，无需输入替换密钥，也不会写入凭据。即使适配器路由尚未注册，渲染器也会保留 Host 返回的错误。

适配器与模型发现使用同一凭据引用、端点和协议。刷新会修复旧版受管配置，同时保留明确允许编辑的端点地址。DeepSeek 回滚同时恢复先前连接和模型目录。配置回滚失败不能跳过凭据恢复，也不能遗留 `checking` 状态。端点没有目录时，手工填写的模型在后续刷新后仍是未验证的 `candidate`，不会获得虚构的验证时间。

<a id="dev-note"></a>
## 开发备注

OpenCode Go 和 Zen 保留持久路由编号，通过 `catalogProvider` 继承对应的内置原生提供方。它们只提供在线目录与内置目录的交集。API 与 URL 的显式 null 值清除旧组合配置中的覆盖，刷新与重启后仍保持原生协议。内置目录尚未描述的模型需要更新客户端，不根据名称猜测协议。

Host 只在通过已认证的模型发现后才提交提供方配置；渲染器快照绝不包含密钥或凭据引用。

## 运行时不变式

不发布运行时不变式伴随入口，因为每个 Remote 响应都是一次串行凭据或设置操作的提交回执，并且不包含密钥值。

<a id="model-experience"></a>
## 模型体验

### 已验证的提供方配置

#### 模型看到的内容

本服务不注册模型可见提示词或工具。后续请求使用已提交的适配器路由和模型目录。认证后的目录结果与手工填写、尚未验证的候选模型分别处理。密钥缺失或被拒绝、端点不可达、响应格式错误或服务不可用时，不返回已验证成功回执。

#### Token 影响

连接检查使用 `GET /models`，不产生模型 Token。普通模型请求只产生所选提供方的正常用量。

#### KV Cache 影响

连接探测不会修改既有会话前缀。切换到另一个已验证提供方会改变请求路由，因此不能复用上一条提供方路由专属的 KV Cache。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- 已认证的目录只证明模型发现成功，不证明推理成功或账号可访问全部所列模型。账号额度和具体模型权限由提供方在请求时判定。
