# @gongchuang/local-automation

[English](README.md) | 中文

## 概述

共创企业助手 V0.1 由 Host 持有的本地自动化注册表。服务把周期任务定义和执行回执保存在 Electron 应用数据目录下，绝不把任务提交到共创云端队列。

<a id="behavior"></a>
## 行为

桌面客户端运行期间，可信客户端会轮询到期任务。被认领的任务通过普通工作区会话 API 派发，因此签名请求、工具和交付门禁仍然生效，模型可见提示也进入常规 Session 日志。提示被接收后，可信客户端还会等待普通结果会话真正结束或失败再结算认领；V0.1 保留的线协议值 `dispatched` 表示终态成功，界面对用户显示为“已完成”。持久化层只保存一次性运行 token 的哈希。

每个任务固定拥有一个专用结果会话。首次手动或定时运行会先创建并持久绑定该会话，再提交提示；后续运行持续追加到同一历史中。会话只是归档时会自动取消归档，本次执行也会在最近对话界面中打开。如果用户已删除绑定会话，或其本地 Session 记录确已消失，下一次认领会创建替代会话，并以旧编号作为比较条件原子换绑。仍存在但已属于其他企业空间的会话不会被隐式移动或替换。

用户也可以在普通会话中要求助手创建计划。范围固定的 `gongchuang_create_automation` 工具只能向当前 Session 所属企业空间写入一项固定间隔任务。签名产品策略把每次调用都归为 `ask`，因此必须先在确认卡片中展示任务名称、周期和首次执行时间，用户同意后才能保存或启用。

一条窄范围的完成声明检查只覆盖明确要求创建计划的会话。它分别跟踪同一轮中的创建结果与已保存任务编号，因此一次成功不能为另一项失败任务或虚构任务编号背书。每轮最多要求纠正一次；部分成功时只要求如实说明，不会重复创建或重试已被拒绝的调用。普通会话文本不受扫描，如实的部分成功、取消或失败说明也不会被拦截。用户进入“自动化任务”页面时，客户端会重新读取 Host 快照，因此会话中确认创建的任务会按已提交的注册表 revision 显示。

首次执行时间必须是有效日历日期并带明确时区。确认卡和任务界面根据已保存周期计算频率，不信任任意说明文字。创建与更新要求目标企业空间仍然存在。已有执行正在运行时不能迁移企业空间，但现有删除操作可以先停止再删除。删除会先持久关闭调度，只移除该任务拥有的排队消息或取消其确切运行轮次，并在执行终止后删除任务。停止失败的任务保持关闭且可重试；会话和文件均保留。提示提交通过上游 Session API，并与删除共用同一条短时变更队列，以运行编号作为请求标识。回执清理只移除已经结束的运行。等待模型和等待停止都不会占用共享变更队列或整页忙碌状态；轮询成功只清除轮询自身产生的错误。

<a id="dev-note"></a>
## 开发备注

可信客户端通过普通工作区 Session API 派发每个已认领运行，并只在该结果 Session 结束后记录成功。

<a id="runtime-invariant"></a>
## 运行时不变式

不发布运行时不变式伴随入口，因为已校验的 JSON 注册表属于私有状态，模型可见的调度会记录到对话会话日志中。

<a id="model-experience"></a>
## 模型体验

### 已认领本地任务派发

#### 模型看到的内容

注册表不直接提供内容。可信客户端认领到期任务或手动运行后，会把 `【本机自动化任务】` 包装文字、任务名称、计划时间、门禁提醒和已保存提示词作为一条普通用户消息发送到所选企业空间。

#### Token 影响

注册表本身不增加 token。任务派发会增加随数据变化的用户消息 token，其长度等于任务包装文字与已保存提示词。

#### KV Cache 影响

任务派发向所选会话追加用户消息，并保留此前可复用的前缀。修改任务不会影响模型上下文，直到后续派发发生。

### 通过会话创建任务

#### 模型看到的内容

工具结构只接收任务名称、完整提示词、带时区的首次执行时间、固定周期、面向用户的周期说明和启用状态。时间或任务内容不明确时，必须先追问，再调用工具。确认卡会按桌面客户端的本地时区展示首次执行时间。只有成功工具结果返回的任务编号才是有效编号。

#### Token 影响

模型会看到范围固定的工具结构和一份精简结构化结果。持久化注册表不会注入后续提示。

#### KV Cache 影响

工具说明对固定专业预设保持稳定。每次调用的参数和结果追加在可复用前缀之后。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与暂缓事项

- V0.1 只在桌面客户端运行时执行到期任务，或在客户端下次启动时补执行；不会安装操作系统后台守护进程。
- 周期目前是至少五分钟的固定本地间隔。日历和文件事件触发要等到 Windows 与 macOS 的平台唤醒和权限行为都完成测试后再实现。
- 删除任务会在其自有执行停止后同步删除保留的运行回执。没有记录请求标识的旧版活动运行需要先在结果会话中停止，再重试删除；系统不会猜测归属并取消手动轮次。如果只删除结果会话，任务仍会保留，并在下次运行时启用一个替代会话。
