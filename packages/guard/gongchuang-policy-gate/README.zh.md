# @gongchuang/client-policy-gate

[English](README.md) | 中文

## 概述

Host 根级分支监听器在跨空间子会话创建前，仅复制继承用户消息引用的产品导入附件。相同内容的目标文件可复用；同名异内容、源文件缺失或路径越界时拒绝，不覆盖文件，也不归档原会话。I/O 中断后已复制文件可供重试复用。此机制不负责同步任意工作区输出文件。

这是共创企业助手的私有产品约束。签名桌面宿主提供按原始字节签名的 Ed25519 策略封套，把策略公钥摘要固定在宿主代码中，并把本次启动实际选中的 Host 已验签技能包中的专业交付合同与技能调用图绑定到同一组合。本 Cordis 原生插件会先独立拒绝替换公钥，再在加载时同步验签并冻结策略；它在首个请求前阻止提供方漂移，让每次工具调用都经过允许、确认或拒绝策略，并要求专业任务激活当前技能包对应的技能、必需依赖和质量检查。本地确定性校验器按当前技能检查候选正文的固定结构、证据状态、来源类型、可复算计算、高企四栏合同及去 AI 味后的事实锁。通过的候选取得正式状态；关键合同缺口只允许一次有限修正，仍未通过就返回带诊断的“待完善稿”；建议项不阻断正式状态；基础能力缺失只返回一次终止失败，不自动重试。正文已校验后若较晚激活的技能展开新依赖，系统会保留已通过候选，先闭合真实激活，再执行最终正文逐字对账。

<a id="behavior"></a>
## 行为

兼容 Hooks 和提示词指令都不是信任边界。正式桌面组合必须使本包不可被用户移除，并让第三方插件经过同一工具代理。回执生产插件只能通过宿主批准的 Cordis 注入边获得私有 `gongchuangPolicy` 服务；仅仅伪造同名工具不能生成回执。长文档原文锁可使用宿主注入的 `sourceToolCallId`。静态 HTML 转 PDF 的 chat 预校验可传 `candidateArtifactPath`，由宿主直接提取真实源文件正文，模型无需逐字复写；最终 PDF 仍须重新执行 artifact 校验与全部交付回执。Office 文件保持原生 OOXML，不作为 PDF 转换源。

每次专业校验的结构化返回均包含 `nextStep`，工具卡片也使用相同文字。PTC 返回结构化值，不自动转发卡片文字。纯聊天候选通过后要求逐字输出；文件预校验通过后要求生成文件并重新执行 artifact 校验；artifact 通过后要求完成剩余可打开性、正文和品牌检查，PDF 另含视觉检查。返回的 `formal` 只表示专业校验通过，不表示文件交付已完成；检索预算通知也保留该区分。文件身份检查和一次修正机会保持不变。

企业全景技能要求用户选择 A/B/C 报告模式时，Host 会记录这项尚未完成的决定；用户回答前只允许激活技能和调用 `ask_user_question`，检索与生成不能把第一项或推荐项当成隐含默认值。带有已签名 `deliveryProfileId` 的正式 Office 候选会在创建文件前通过聊天模式结构校验，创建后再通过文件模式校验。没有自有签名交付画像的技能会收到明确提示：省略该可选 ID，不借用其他技能的画像。

任务意图路由排除同一逗号、分号或句子分隔范围内被明确否定的动作。文件读取请求中排除政策查询、企业资料或报告生成时，仍按普通任务执行。“不能冒充官方政策”等来源约束不激活政策检索；“为什么不能申报”等资格问题仍需处理。后续分句中肯定的专业请求仍激活所属技能。否定表达不授予工具权限，也不豁免已激活专业任务的校验。

完整分句只说明技能职责范围，或约定缺证据时保留未知状态，不等于要求执行被提及的业务。额外的肯定分析请求仍激活相应校验；不会按技能名称直接豁免，也不会授权发布。

仅抄录已有字段、数字或引用原文，且没有肯定的分析或文件制作动作时，按普通查询执行。注释评论中的政策名称、未核验状态不单独重启被引用的旧任务；同时要求申报资格判断时仍进入专业校验。

用户明确限定只按给定规则核算，并排除现实政策和资格判断时，聊天核算不会仅因主技能依赖政策检索而要求官方政策原文。范围由宿主读取用户意图确定，不接受模型任务名称作为依据；复算、证据绑定和修复次数限制仍生效，候选正文须说明不构成资格结论，不得声称有权获得补助。政策主任务、肯定的资格判断请求和正式文件仍要求官方来源。此有限意图识别不证明业务结论的语义正确性。

以同行比较为主任务且用户明确限定给定样本时，聊天比较不要求另取公开企业或政策来源。范围由宿主从用户请求识别，候选须披露仅限样本，不能断言市场领先、市场份额或申报资格；真实读取绑定和复算仍须通过。政策主任务、正式文件及要求现实市场结论的请求保留相应来源要求。

证据绑定与可独立执行的正文检查在同一次调用中返回已有诊断。未绑定数据只用于发现结构、复算等问题，绝不能生成通过回执。诊断区分缺少客户文件读取回执与原文片段不匹配；任意脚本输出不被当作受信任文件读取。修复次数不增加，避免先修一项后才看到另一项已存在的问题。

普通轮次加载总控或路由技能，不单独启动专业任务。总控同时拥有通用文档读取器，真实激活后仍可使用其签名操作；明确业务请求或具体专业技能仍正常启动对应检查。

客户端提供 `source.displayText` 时，任务路由使用该现有用户可见投影，并排除附件引用行和历史注释摘录。产品补充的读取指引、附件文件名不能单独选择业务任务；完整模型消息和工具授权保持不变，没有显示投影的调用方仍按文本路由。

工具完成时保存交付检查点，不在模型工具调用与对应结果之间追加用户可见通知。下一次 pre-step 或 turn-stop 边界在工具交互完成后发布去重状态通知，保留完整工具结果和原有校验结论。

返回终态 `draft` 或 `failed` 后，宿主拒绝同轮下一次模型步骤，并记录缺口与保留文件入口；没有生成文件时也显示诊断。停止不依赖模型遵守工具返回的文案，只有用户在后续轮次明确发起修订才重新获得修正机会。

PTC 成功加载技能后，通过已有附加上下文通道在根工具结果之后保留完整技能指引。SDK 程序只打印简短摘要时，不会静默丢失后续工作流。直接调用技能的结果已包含正文，不重复添加。

同一调用前策略拒绝 Bash 和 PowerShell 中的直接永久删除命令，包括串联的 `rm` 和 `Remove-Item`，并要求保留现有文件、改用授权范围内的新路径。此有限检查不解释任意程序效果、编码命令或间接调用，不能替代操作系统隔离。

<a id="version-lines"></a>
## 版本线

客户端版本读取 `product/gongchuang-client/src/product-version.ts`；活动技能版本来自 Host 已验签的实际安装包。文档示例和测试夹具不能作为当前安装版本的声明。

计算的 `evidenceIds` 只引用证据数组，不引用其他计算 ID。派生计算沿用输入的原始来源证据 ID，拒绝诊断明确解释两者区别，不放宽复算和来源绑定。行内箭头分隔的流程序号、明确标注的清单项数限制属于排版信息，同一行中的业务金额仍须证据支持。

签名产品策略固定客户端随包基线。专业合同与固定操作另行绑定到本次启动由 Host 验签选中的准确技能版本，因此独立签名更新不会仅因版本高于随包基线而被拒绝。

<a id="config"></a>
## 配置

```yaml
- id: gongchuang-policy-gate
  name: '@gongchuang/client-policy-gate'
  config:
    manifestPath: /managed/policy.json
    signaturePath: /managed/policy.sig
    publicKeyPath: /managed/policy.pub.pem
    expectedPublicKeySha256: <64-lowercase-hex-host-anchor>
    expectedProductId: cn.gongchuang.enterprise-assistant
    expectedClientVersion: 0.4.0
    expectedSkillBundleVersion: 1.6.15
    activeSkillBundleVersion: 1.6.15
    professionalContractsPath: /managed/skill-suite/skills/delivery-contracts.json
    skillCallGraphPath: /managed/skill-suite/skills/skill-call-graph.json
    professionalCheckpointDir: /managed/user-data/professional-tasks
```

公钥、宿主固定的公钥 SHA-256、两个版本输入和全部路径均为必填。两个专业合同路径必须指向桌面宿主逐文件验签的同一当前技能包，不得指向用户可写目录；检查点目录必须位于宿主管理的当前用户数据目录，不能放进活动技能包。本插件不存在开发绕过或未签名回退路径。插件直接导入与产品 UI 共用的 V0.4.0 准确提供商注册表，并固定默认拒绝无归属工具、原始命令禁用、产品必需工具、专业回执及四种正式文件回执身份，因此即使有人用有效密钥给弱化策略签名，插件仍会拒绝加载。

<a id="model-experience"></a>
## 模型体验

### 请求、工具与交付约束

#### 模型看到的内容

被允许的模型提供方和工具保留原有内容。被拒绝的工具沿现有工具结果失败路径返回策略原因；未进入签名允许列表的模型提供方会在请求推导前被拒绝。一次性 Bash 或 PowerShell 脚本在产品工作区内允许执行，用于调用内置 Python、Node.js 和已验签技能脚本；交互式终端、后台任务、子代理和工作流工具仍直接拒绝。浏览器和计算机自动化必须取得用户确认。专业任务会收到技能包版本和必需技能通知，并把精确候选、证据台账与可复算计算交给 `gongchuang_professional_validate`。宿主把已核验证据绑定到本轮受信任读取或来源调用，校验真实文件正文，并在发布前重新打开正式文件。关键缺口第一次返回 `repairable`，第二次返回 `draft`；基础能力缺失返回终止 `failed`；建议缺口保持可见但不阻断 `formal`。最终 PDF 仍须取得宿主逐页视觉回执。候选漂移、强制结构缺失、可执行回执失败、文件变化、用户退回，或同一 V0.4.0 轮次出现多个最终正式文件路径时仍不能取得正式状态，但用户会得到已标记的待完善稿和诊断，而不是进入无限纠正。专业首步和新增依赖通知均按当前工具目录说明调用通道。仅开放 `run_code` 时，技能、提问及专业校验通过程序内的 `tools` 调用，不直接调用未开放的根工具；未激活技能的固定操作返回相同的通道指引。该提示不改变技能激活、回执归属或修复次数。

##### 较晚依赖纠正

```markdown
If a successful skill activation expands new dependencies after a chat candidate has passed validation, the correction identifies content validation as complete and requests only the missing real skill activations. It does not expose an internal digest, compare the candidate, or repeat the body at that stage. Once activation closes, an exact mismatch may include the retained candidate once. No dependency is marked active without a successful `skill` result, and evidence and candidate identity checks remain unchanged.
```

#### Token 影响

普通任务不增加策略 token。专业任务增加首步版本与技能锁定通知，以及一次结构化本地校验工具调用；`repairable` 后至多追加一次纠正消息。较晚展开依赖时只携带短检查点，同一已校验正文在不一致纠正中最多附带一次。确定性校验器本身不消耗模型 token，被拒绝的模型提供方也不会消耗模型 token。

#### KV Cache 影响

策略为获准工作保留现有请求前缀。纠正消息仅追加到同一会话历史；策略或模型提供方拒绝会阻止请求，而不是替换已缓存内容。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- PDF.js 只能把带有可靠文本映射的 PDF 正文纳入确定性校验；纯扫描 PDF 或缺少可用字符映射的文件必须改用源 Office/HTML 文件，或在后续候选中接入同样受宿主约束的 OCR 正文回执，不得使用模型猜测文本。
- 宿主证据证明只能确认证据取值、网址和摘要出现在本轮用户输入或受信任工具内容中，不能单独证明来源具有权威性，也不能证明自然语言结论必然由来源语义推出。仍须执行当前已签名技能包的来源选择规则、确定性计算、冲突披露和人工复核。
- Office 文件默认由签名 Python OOXML 库直接生成，不经过 LibreOffice 或 Office 转 PDF。用户明确要求 PDF 时才从静态 HTML 经 Electron Chromium 生成，随后由随包 PyMuPDF 完成正文解析、逐页栅格化和同源自动视觉回归。
- V0.4.0 每轮只校验一个正式文件路径；多个交付物必须分轮取得独立回执。
- 一次性 Bash 或 PowerShell 执行依赖桌面宿主注入并核验的 Python 与 Node.js 运行时；缺失运行时会明确失败，不得把脚本执行退回用户手工完成。交互式终端和后台命令仍不开放。
- 桌面宿主仍必须阻止绕过工具代理的进程、文件、浏览器和网络通道。
- 代码签名、公证、安装器升级、回滚和干净设备验收属于发布门禁，不由本包实现。

**运行时不变式：** 不发布运行时不变式伴随入口，因为签名与身份检查会在监听器之前同步执行，通过检查的策略保持不可变，不形成可独立观察的关系。
