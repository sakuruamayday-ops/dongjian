# @gongchuang/connectors

[English](README.md) | 中文

## 概述

工作区 PDF OCR 接受可选的 `pages` 页码列表，直接使用已签名读取器返回的 `ocr_pages`。已验证的内置 PyMuPDF 在内存中选页，不要求模型编写拆页脚本或产生临时文件；结果保留原页码，缓存按原文件和所选页区分。文件发布接受绝对路径或当前会话工作区相对路径，不以桌面进程的启动目录解析相对路径。该操作只向当前会话添加本地文件入口，不上传文件，不发布软件或技能，也不切换正式版本。

共创企业助手私有可信连接器管理器。它提供生成式 Remote 状态与配置接口，并且只装载固定、已审查的集成：企查查官方 Streamable HTTP MCP、天眼查官方 Streamable HTTP MCP、PaddleOCR 官方 MCP，以及内置的共创证据检索包装器。

## 行为

配置中只保存凭据引用。真实密钥仅由宿主在建立连接或发起请求时解析，绝不返回浏览器。

已保存凭据的状态读取失败时，对应连接器会显示可重试错误，并保留已存启用状态和凭据元数据；其他连接器仍会继续协调。操作系统恢复访问后，刷新会重读同一引用，无需填写新 API Key。

启动对账会在连接器服务挂载后执行。相互独立的连接器定义并发对账，企查查固定的十个服务端点并发建立连接并发现工具，再按确定顺序汇总结果。凭据库响应较慢或暂时不可用时，只影响对应连接器卡片，不会阻塞桌面主窗口、普通会话或不需该凭据的其他连接器。用户主动配置和刷新仍会等待真实凭据结果。所有可执行连接器依赖都随已签名运行时分发，首次使用绝不会安装到用户缓存。

管理器会消费 MCP supervisor 不含凭据的连接生命周期。传输中断后会立即显示重连中或不可用，不再保留过期的“已就绪”状态；重新发现工具成功后恢复就绪，重试预算耗尽后必须由用户显式刷新。企查查由多个服务组成，仍可用的服务会继续保留，并把故障子集显示为“部分可用”，而不是整卡伪绿。

企查查默认使用官方 OAuth 登录：宿主动态注册本机客户端，使用 PKCE 和仅监听 `127.0.0.1` 的临时回调完成授权，并在系统凭据库中保存访问令牌、刷新令牌及到期元数据。访问令牌到期前由宿主自动续期；手动粘贴官方 API Key 仍作为备用方式，并会清除旧 OAuth 续期信息，避免两种认证来源相互覆盖。无论采用哪种方式，只有官方 MCP `tools/list` 实际返回工具后才显示已就绪。

天眼查默认使用官方 OAuth 设备授权。宿主核对固定的受保护资源与授权服务器元数据，动态注册本机客户端，渲染器只得到官方授权地址、用户授权码和不透明事务标识。访问令牌、刷新令牌和动态客户端元数据都留在系统凭据库；宿主会自动续期临近过期的访问令牌，并在 `tools/list` 通过后才显示就绪。“我的 Key”仍作为备用方式，手工配置后会清除旧 OAuth 状态。天眼查 MCP 与 CLI 共用账号额度；额度耗尽与身份失效分别显示。

连接器管理器还持有用户确认的四地市检索范围。杭州、绍兴、金华、宁波会通过 `X-Jiaotang-Region` 发送给共创知识服务；“默认（全部）”不按城市收窄。市级与区县级内容按当前城市收窄，浙江省级和国家级项目、通知作为四地市共享层始终保留；名单类查询仍按当前城市收窄，避免把全省或全国企业名单误当本地名单。切换所属地会重新装载知识连接器，使后续知识调用立即使用新范围，而任务参数中已经明确出现的地区不会被默认值覆盖。每次修改都会携带渲染器最后看到的 Host 地区；Host 会拒绝过期修改，避免延迟的启动操作覆盖从磁盘恢复的地区。

<a id="dev-note"></a>
## 开发备注

连接器密钥始终保持为凭据引用；只有 Host 验证凭据并从官方端点发现工具后才会发布就绪状态。

## 运行时不变式

不发布运行时不变式伴随入口，因为连接器发现与调用都是请求范围内的 Host 操作，本包不持有持久事件关系。

<a id="model-experience"></a>
## 模型体验

### 已就绪连接器工具集

#### 模型看到的内容

连接就绪后会注册 `mcp__*` 服务器限定工具；停用、未配置或失败的连接器不向模型提供工具 schema。

#### Token 影响

每个就绪连接器会增加自己的 MCP 工具 schema；只有模型调用相应工具时才会增加结果 token。停用或失败的连接器不增加 token。

#### KV Cache 影响

就绪工具集不变时，重复的系统提示词前缀保持稳定。启用、停用、重新连接或上游工具列表变化会重建这部分内容，并可能使模型提供方无法复用变更位置之后的缓存。

### 纯文本模型路径的 OCR 回退

#### 模型看到的内容

每张已解析图片会以 `图片 OCR 文字识别结果` 为标题向模型提供 PaddleOCR 文本，随后附带固定能力限制和审计行，审计行包含源图 SHA-256、切片数与本次断点复用切片数；仍有图片未解析时，系统会在模型请求发出前拒绝该请求。高度超过 3,400 像素且纵横比不低于 2.6 的图片会先在本机切片再上传；切片优先选择视觉能量较低的横向区域，保留受限重叠，并且只删除边界处完全相同的 OCR 行，不会模糊合并政策数字、名称或日期。每个切片都有确定的 SHA-256，进程内最多保留 64 个成功切片的文字结果，使长截图中断后可续传且不建立第二套持久缓存。PaddleOCR 在用户明确配置 AI Studio 前保持停用；每次装载先通过百度 AI Studio 官方 API 校验访问凭据，再启动受签名的固定 PaddleOCR MCP 运行时并执行 `tools/list`，两项均成功才提交凭据并显示就绪。启动校验不会创建 OCR 作业、上传测试图片或消耗识别任务；真实 OCR 能力由独立功能验收覆盖。V0.1 启用后，用户明确提交的图片切片会离开设备并发送到百度官方服务，这不是本地推理。

#### Token 影响

OCR 文本和能力限制会增加随数据变化的用户消息 token，Host 将每张图片的结果限制为最多 120,000 个字符。

#### KV Cache 影响

回退处理会在待发送用户消息的后缀中用文字替换图片字节。更早的会话历史保持稳定；不同 OCR 结果只改变该后缀。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- 天眼查连接当前官方 `https://mcp.tianyancha.com/mcp` 地址。小工具面负责主体锚定与能力发现，深层业务维度通过服务端能力目录和代理工具按需调用，避免把 162 个工具全部注册进每轮模型上下文。
- 天眼查设备授权仍需用户在官方页面完成登录与同意。免费接入受天眼查账号额度限制，不是客户端承诺的无限权益。客户端直接消费官方 MCP，不把天眼查另行维护的场景 Skill 仓库复制进内置技能包。
- PaddleOCR V0.1 通过已签名产品运行时中的精确 Python 可执行文件，运行经过审核的 `paddleocr-mcp` 0.8.5 模块。启动参数固定使用 `aistudio` 云端推理源，因此不会导入 `paddlepaddle`、加载本地模型或静默回退到上游默认的本地引擎。它不会解析 `uvx`、不会在首次使用时下载软件包，也不会回退到 `PATH`；桌面发布门禁必须在两个平台分别核验内置模块、发行元数据、Python 树、云端模式 `tools/list` 与一次真实 OCR 结果。
- 企查查网页登录仍需要用户在系统浏览器中完成官方登录和授权；客户端不会代填账号、密码，也不会把授权页面嵌入渲染器。
