# Windows 10/11 x64 真机验收

## 使用前提

- 使用干净的 Windows 10 或 Windows 11 x64 测试账号。
- 当前账号不得已经安装共创企业助手；脚本检测到现有安装会停止，避免覆盖正式数据。
- 将完整内部测试包目录复制到 Windows 本地磁盘并解压，不要直接从压缩包、U 盘或网络共享运行。
- 安装 Windows SDK，并确认 PowerShell 中能够调用 `signtool.exe`。缺少该工具时验收会失败，不能手工跳过。
- 本轮是 V0.4.0 Windows x64 正式候选。常规正式发行仍要求 NSIS 安装器、主程序、卸载器、更新辅助程序和随包可执行文件使用同一固定组织发布者的 SHA-256 Authenticode 与 RFC 3161 SHA-256 时间戳；V0.4.0 沿用已确认的未签名 Windows 例外边界，因此本脚本不构成当前版本的真机通过证据，发布记录必须明确保留静态验收范围。包内运行时和 V1.6.15 技能继续使用 formal 层级签名。

## 运行方法

双击解压目录中的 `acceptance/run-windows-device-acceptance.cmd`。

脚本会自动执行：

1. 从 `windows-test-package.json` 读取并校验当前 V0.4.0 候选的身份、签名状态及 SHA-256；哈希仅用于内部验收，不作为用户下载项或“打开方式”。
2. 用 Windows 信任链和 SignTool 核验安装器，并在安装后逐文件核对全部 `.exe`、`.dll`、`.node`、`.pyd` 的发布者、SHA-256 和 RFC 3161 时间戳。
3. 核对 x64 主程序、formal 签名运行时、V1.6.15 技能、窗口和日志。
4. 验证关闭主窗口后客户端隐藏到系统托盘而不退出，再仅为继续自动验收而终止测试进程。
5. 暂时移走运行时签名并确认客户端失败关闭；脚本在同一失败测试事务内恢复签名并验证正常启动。
6. 将测试安装目录移入 Windows 回收站，运行已验签卸载器清理注册表和快捷方式。
7. 验证用户状态未被卸载误删，重新安装同一候选并复核其身份、逐文件签名、用户状态和主窗口。
8. 生成机器信息、全部阶段、截图、日志和 JSON 回执；回执只记录实际核对过的当前候选、发布者、运行时索引和技能索引身份。

## 自动验收完成后

脚本会打开最新证据目录，并把 `WINDOWS-MANUAL-SMOKE-CHECKLIST-zh.md` 复制到其中后用记事本打开。继续按清单完成登录、三路模型、技能中心、MCP、自动化、企业空间、键盘和错误复制等真实操作；不要只运行生命周期脚本就把 Windows 使用验收标记为通过。

请把整个证据目录发回，至少应包含：

- `windows-device-acceptance.json`
- 自动验收实际生成的窗口与失败关闭截图
- 各轮主进程日志
- 填写后的 `WINDOWS-MANUAL-SMOKE-CHECKLIST-zh.md`
- 手工冒烟清单要求的截图

生产登录、下载和更新状态以测试时服务端的真实响应为准。没有服务端请求日志或客户端成功回执时不得填写通过，也不得把 404、无响应或缺少更新清单显示成“已是最新版”。
