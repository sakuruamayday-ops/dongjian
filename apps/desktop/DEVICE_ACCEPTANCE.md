# 共创企业助手 V0.2.6 实机验收

本文档只用于未发布候选版的安装测试。Windows 常规正式候选应由固定组织发布者完成 Authenticode 签名；安装器、主程序、卸载器、更新辅助程序和全部随包 PE 文件都应使用 SHA-256 并带 RFC 3161 SHA-256 时间戳。V0.2.6 沿用主人明确接受的未签名 Windows 例外边界，不得把静态检查或 V0.2.0 历史真机回执表述为 V0.2.6 已签名或已完成真机验收。包内运行时和技能仍须通过 formal 层级签名验证。

## Windows 10/11 x64

必须在没有正式共创客户端的干净 Windows x64 测试机上执行，并预先安装可从命令行调用 `signtool.exe` 的 Windows SDK。脚本会拒绝覆盖已有安装，并且只允许把验收实例安装到当前用户的 `LOCALAPPDATA` 之内。

```powershell
apps\desktop\scripts\run-windows-device-acceptance.cmd
```

脚本必须在可交互桌面会话中运行，它会生成正常启动页面与失败关闭对话框截图。全部步骤包括：

1. 从同目录的 `windows-test-package.json` 读取安装包、版本、固定发布者、索引和内部验收哈希，拒绝错包。
2. 对 NSIS 安装器执行系统信任链、固定发布者、SHA-256 和 RFC 3161 SHA-256 时间戳核验。
3. 安装当前 V0.3.1 候选，检查 x64 主程序、formal 签名运行时、51 个 V1.6.13 技能、`app.asar` 身份及主窗口，并逐一核验安装目录内所有 `.exe`、`.dll`、`.node` 和 `.pyd`。
4. 关闭主窗口，验证进程隐藏到系统托盘并继续运行；脚本随后只终止验收进程以继续测试。
5. 暂时移出运行时签名，验证客户端不会进入正常主界面；脚本在同一失败测试事务内恢复签名并再次启动。
6. 将测试安装文件移入 Windows 回收站，再运行已验签卸载器清理注册表和快捷方式，并验证用户状态保留。
7. 重新安装同一候选，复核 `app.asar` 身份、逐文件签名、用户状态及主窗口。

证据目录默认位于 `%LOCALAPPDATA%\GongchuangAcceptance\Evidence-<timestamp>`，其中包含：

- `windows-device-acceptance.json`：包含设备、固定发布者、签名与时间戳证书、每个随包 PE 的 SHA-256、运行时索引、技能索引和逐步结果；回执与日志、截图作为一个证据目录共同复核，不生成可与 JSON 一同改写的裸摘要旁文件。
- 自动验收实际生成的启动或失败关闭截图。
- 每次启动的新增主进程日志。

脚本不收集 API Key、账号密码或企业材料。不得把安装包或验收回执上传到公开仓库。
