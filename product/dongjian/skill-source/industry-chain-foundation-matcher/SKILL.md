## 适用边界

- 产业链只使用 `references/industry-chain-index.jsonl` 中的原始层级路径。
- 产业基础只使用 `references/industry-foundation-index.jsonl` 中的领域、五基类别和产品技术名称。
- 两份原始 PDF 已随技能保存在 `references/source-documents/`，需要核对上下文、版式或索引疑点时直接查阅原文。
- 原文件《产业基础创新发展目录（2021年版）》采用“五基”口径。用户说“工业六基”时仍触发本技能，但不得虚构第六类。
- 申报表的六个勾选项与目录五基并非完全同名。按 `references/classification-rules.md` 映射，并保留来源口径与表单口径两列。
- 目录命中只表示分类相符，不表示企业必然符合项目条件，更不表示一定获批。
- 两份文件作为同一套分类资料共同生效、共同更新。在用户明确告知整套资料过期、失效或被新版替代前，均视为当前默认有效的分类依据。不得把“默认有效”表述成“已核验为官方最新版本”。

## 工作流

1. 收集企业主导产品名称、用途、材料或软件属性、核心工艺、客户行业、上下游位置和可核验证据。
2. 使用 `scripts/search_catalogs.py` 检索候选，或直接逐条查询两个 JSONL 索引。报告检索数量时注明检索词与范围，引用 `search_summary`，不要把返回前 N 条当作全部结果；`normalized_term_matches` 只表示规范化整词包含数，不表示业务匹配。
3. 先判产业基础目录，再判产业链路径；不得只凭企业经营范围或宽泛行业名称匹配。
4. 对候选逐项比较对象、功能、材料、工艺、应用场景和产业环节。已检出但不适用的条目保留原词、来源位置与排除理由，不得改写为“检索未命中”；关键词没有整词命中但有模糊召回时也须区分。
5. 按“精确匹配、近似匹配、未命中”三级输出，并给出来源文件、页码和原始分类。
6. 在专精特新或小巨人体检中，将结果与主导产品、核心技术、客户验证、补短板叙事及有效授权 I 类知识产权交叉校验。
7. 每次输出标注两份来源文件、对应页码、《产业基础创新发展目录（2021年版）》的版本年份及“默认有效”状态。产业链架构不单独标注机构和日期。

## 判定规则

### 精确匹配

只有目录原词与企业产品技术在对象和实质功能上明确一致，且企业资料能证明该产品或技术已实际形成时，才判精确匹配。不得因关键词相同直接命中。

### 近似匹配

没有精确条目时，必须同时输出：

1. 一个目录内最相似的产品或技术，说明相似点和关键差异，明确标注“近似目录项，不等于正式命中”。
2. 一个最可能归属的现有产业链路径，明确标注“推定产业链”，列出推定依据和仍需补充的证据。

不得创造目录中不存在的条目或层级。若连合理近似项都无法找到，写“当前目录未命中可靠近似项”，不得强行挂靠。

### 冲突处理

- 企业自述与目录冲突时，以目录原始分类为准，企业自述只作为待核验线索。
- 同时命中多个路径时，优先选择与主导产品收入、核心技术和主要客户直接对应的路径，其余列为备选。
- 当期申报通知另有分类口径时，分别呈现“目录匹配”和“当期通知适用性”，不得相互替代。

## 输出格式

| 项目 | 结论 |
|---|---|
| 匹配等级 | 精确匹配 / 近似匹配 / 未命中 |
| 产业链路径 | 目录原始完整路径或推定路径 |
| 产业基础领域 | 21 个领域之一 |
| 目录五基类别 | 原始五基类别 |
| 申报表六基建议 | 对应勾选项或无法确认 |
| 原始目录项 | 产品或技术原词 |
| 匹配依据 | 产品、功能、材料、工艺、场景、环节 |
| 差异与风险 | 不一致点及挂靠风险 |
| 证据缺口 | 需要补充的合同、检测、专利、项目或产线证据 |
| 来源 | 两份文件名、对应页码、六基目录版本年份、索引记录 |
| 来源状态 | 默认有效；尚未收到过期或替换通知 |

近似匹配时，追加“相似目录项”和“推定产业链”两段，不能把推定结果写成目录原文。
