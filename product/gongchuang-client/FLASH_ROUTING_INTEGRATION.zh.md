本客户端没有复制或打包上游发布包，而是在共创自有 Cordis 插件中改写并吸收下列通用方法：

1. 根据当前用户消息区分续接任务与新任务，并执行任务分类。
2. 在 `agent/pre-step` 已组装请求内调用 `next()` 后，把短小近场引导追加到同一次真实用户请求，降低多轮对话中的指令稀释，不产生第二次模型调用。
3. 复杂任务先回顾既有进度，再检查边界、集成点与失败路径。
4. 简单任务快速收敛；信息完整后立即产出，避免重复检查和偏离目标。

2026-08-25 的最新审阅覆盖套装将子模块平铺进单仓库及未发布的
router-standard v1.19.1/v34 研发线。该变化没有形成新的正式 Release，
也不改变本产品已经验证的同请求近场引导接口，因此只更新审阅基线，
不替换方法采用提交，不带入其开发注入器、首轮工具隐藏或研发预设。

## 共创适配边界

以下上游能力不进入产品：

- 不采用 router-standard 的 standard 模式清空 system sections。
- 不替换共创 persona、专业技能规则、用户指令或现有 plan-mode。
- 不裁剪工具目录为 shell 与 editor，也不在首轮隐藏技能、MCP、搜索或文档工具。
- 不打包 `dsh-super-injector`、运行时热注入器及其开发管理工具。
- 不注册 `dev_router_*`、`dev_mode_*` 或模式隔离开发子代理。
- 不采用上游首轮工具渐进披露、交付门禁或额外注入事件；共创既有工具、技能、安全、完整性与发布规则继续作为唯一产品实现。

增强按模型身份生效：任意已连接服务商上的 DeepSeek V4 Flash、Flash Free 与 Pro 都会获得同一组路由提示。这样 DeepSeek 官方、OpenCode Go、硅基流动、Orgarid 与用户自行添加的 OpenAI 兼容服务保持一致；不匹配这些模型的会话完全不受影响。普通问答、联网检索、创作与用户自行安装的第三方技能保持开放；命中共创专业业务时，原技能包的事实边界、证据规则和默认模板继续优先执行。
