# Agent Note: 仅在消费者实际校验时保留摘要

Status: implemented

[English](2026-08-20-consumer-owned-digests.md) | 中文

## 问题

共创客户端部分路径逐渐积累了没有下游消费者校验的 SHA-256，或把摘要格式误当成来源权威性、页面唯一性的替代判断。这些值增加了 I/O、持久状态和失败条件，却不能阻止具体的完整性故障。同一代码库中，签名发布索引、正式文件绑定、内容寻址安装身份和缓存仍使用承担实际职责的摘要，因此不能无差别删除。

## 决策

只有当明确的消费者会校验身份、完整性、缓存归属或内容寻址时才保留摘要。签名运行时与技能索引、更新清单、正式文件绑定、归档安装身份，以及 OCR 或附件缓存继续保留摘要。

文档导入只返回复制后的文件名、企业空间相对路径和字节数。社区技能注册表保留来源、归档身份、配置状态和元数据，不再保存未使用的仓库清单摘要或逐文件摘要清单。读取注册表时先去掉这些旧字段，再在下一次写入时完成清理。

专业来源分类不再把 64 位摘要当成权威性证据。政府网址，或本轮 Host 回执与已声明来源类型的组合，负责这项判断。Host 计算的摘要仍绑定受信任工具的精确输出，但不能把任意来源升级为官方来源。视觉回执继续要求有效页码、尺寸和 PNG 摘要格式；不同页码可能合法地呈现相同像素，因此允许共享 PNG 摘要。

桌面技能打包器省略每个技能独立发行所需的 `release-manifest.json`、分离签名、发布公钥和签名元数据。独立技能发行包继续保留并校验这些文件。客户端内由宿主固定的单一 Ed25519 顶层索引覆盖所有实际装入文件；客户端专用投影还会从已装入的 `SKILL.md` 中移除受管便携运行区块，避免技能激活后要求模型执行一个因独立证明文件有意缺失而无法完成的 `prepare` 命令。当前 V1.6.7 源树实际装入 550 个客户端文件，204 份独立发行证明文件和全部独立 `prepare` 指令均未进入客户端，顶层签名清单保持完整。

实机验收只生成一份 JSON 回执，并配套日志与截图，不再生成可与 JSON 一起被改写的同目录摘要旁文件。JSON 记录设备实际核对的正式签名层级、运行时索引和技能索引。整个证据目录用于人工复核，不宣称在传输后具备密码学意义上的设备证明。

## 已考虑的替代方案

- **删除全部 SHA-256。** 不予采纳，因为签名索引、下载产物、正式文件、缓存和内容寻址安装具有真实消费者和明确的失配故障。
- **为可能出现的未来消费者保留未使用值。** 不予采纳，因为未来完整性能力在引入时必须同时定义生产者、消费者、失败行为和恢复路径。
- **让设备回执自签或随包分发签名秘密。** 不予采纳，因为未经注册的本机密钥不能证明发布身份，而分发发布私钥会破坏签名边界。
- **从所有发行形式中删除技能独立签名。** 不予采纳，因为 Codex、CodeBuddy 和其他独立安装仍需逐技能验证发布者。

## 后果

- 导入过程避免第二次完整读取文件，社区注册表写入更小，用户看到的已安装状态不变。
- 既有注册表仍可读取，废弃的摘要清单会在下一次状态变更时消失。
- 本地官方文件和名单必须绑定 Host 回执，政府网页仍通过政府网址识别。
- 空白页或有意重复的渲染页不会仅因 PNG 字节一致而失败。
- 新构建的客户端技能包及验收输入必须使用包含 550 个文件的签名索引。既有 752 文件候选和历史回执保持历史原状，不做改写。
- 独立技能包保留现有 Ed25519 首次运行流程；客户端获得单独签名的指令投影，并继续保留顶层签名完整性边界。
