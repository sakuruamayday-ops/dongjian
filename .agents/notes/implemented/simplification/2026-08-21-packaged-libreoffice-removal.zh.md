# Agent Note: 移除安装包内置 LibreOffice

Status: implemented

[English](2026-08-21-packaged-libreoffice-removal.md) | 中文

## Problem

桌面运行时此前内置完整 LibreOffice，用于 Office 转 PDF 和逐页渲染。签名 Python 文档运行时已经可以直接生成并重新打开 DOCX、XLSX、PPTX 和 PDF，而 LibreOffice 占据了分平台运行时的大部分体积，并增加每次启动的验签与加载工作。把缺少 LibreOffice 直接视为正式交付失败，还会导致模型反复重试宿主根本无法执行的视觉操作。

## Decision

V0.1.4 桌面运行时保留签名 Python 文档与 OCR 依赖，不再包含 LibreOffice 目录、可执行文件、字体副本、环境变量或 `PATH` 项。运行时暂存、签名索引、启动验签和打包预检只暴露并核验 Python 这一项文档运行时可执行文件。四格式冒烟测试继续通过固定版本的 Python 库生成并重新打开真实 DOCX、XLSX、PPTX 和 PDF 文件。

Office 逐页渲染属于可选宿主能力，不再视为 OOXML 生成天然具备的能力。宿主注册经过审查的渲染器时，正式交付仍须取得逐页回执。宿主没有渲染器时，策略只注入一次能力限制提示，继续要求可打开性、正文、品牌、专业校验和最终文件发布回执，并要求最终回答明确披露未执行逐页视觉验收。缺少渲染器不会被记作视觉回执成功。

本决策部分取代[分平台运行时精简](2026-08-17-platform-runtime-pruning.zh.md)中保留 LibreOffice 及其链接验签的内容。该记录关于 Python 依赖、缓存清理、原生模块选择、签名文件树和四格式生成的决策仍然有效。

## Alternatives considered

**所有平台安装包继续保留 LibreOffice。** 不采用，因为 Python 链已经负责文档生成和结构性重开，而内置办公套件占据运行时主要体积并增加启动验签成本。产品可以如实披露未执行精确逐页渲染，没有必要为每台设备强制附带该负担。

**把 OOXML 成功生成视为逐页视觉验收。** 不采用，因为压缩包结构与应用级重开不能证明分页、裁切、字体替换、图表布局及其他页面渲染表现。

**删除视觉回执要求但不披露。** 不采用，因为这会静默弱化正式交付结论。缺失能力必须在模型指令和最终面向用户的结果中保持明确。

## Verification

定向暂存与验签测试拒绝旧的多可执行文件索引，并接受精确的 Python 单运行时签名文件树。打包输入验收对每个目标平台运行固定 Python 依赖和四格式生成冒烟测试。策略测试证明缺少渲染器时只出现一次能力限制提示，其他可执行回执继续有效，且不会形成无限续轮。最终安装包验收记录运行时文件数、签名索引身份、安装包体积，并确认不存在 LibreOffice 可执行文件。

## Consequences

各平台运行时和安装包显著缩小，启动也不再验签 LibreOffice 文件树。客户端继续生成并重新打开四种受支持文档格式，签名技能脚本与 OCR 执行能力不受影响。客户端默认不提供本地 Office 转 PDF 或逐页渲染，因此只有后续接入经过审查的宿主渲染器时，才能形成逐页视觉验收结论。
