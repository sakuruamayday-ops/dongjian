# Agent Note: 连接器并行启动与 Windows 包体

Status: implemented

[English](2026-08-24-connector-parallel-startup-and-windows-footprint.md) | 中文

## 问题

互不依赖的 MCP 连接原本串行对账，企查查还会依次对 10 个端点重复连接和发现。Windows 上会累加网络延迟。安装包还携带了全部 Electron 语言包，而体积较大的签名 Python 运行时和应用归档有时被误认为可随意清理的缓存。

## 决策

互不依赖的顶层连接器并行对账。企查查的 10 个端点并行连接与发现，随后按配置的固定顺序合并结果。失败仍按连接器隔离，也不增加首次使用安装依赖。

Windows 包只保留 `zh-CN` 和 `en-US` Electron locale。签名 Python 运行时、`app.asar` 和一个更新待安装包继续保留，因为它们承担离线文档/OCR、应用代码、完整性验证和可恢复更新。

## 曾考虑的替代方案

**移除随包 Python 运行时。**不采用，因为这会破坏离线 Office/PDF、OCR 和签名运行时保证。

**激进删除更新缓存。**不采用，因为一个待安装包属于可恢复更新，永久删除也与工作区安全规则冲突。

**按连接完成顺序发布工具。**不采用，因为网络时序会使工具顺序不可确定。

## 后果

连接延迟可以重叠，而投影的工具顺序仍稳定。Windows 解包去掉约 46 MiB 无用 locale，其余体积主要是真实离线能力。单元测试和跨构建测量已完成，Windows 原生启动/MCP 时间和安装后体积仍属于设备证据。
