# Agent Note: 共创客户端签名策略边界

Status: implemented

[English](2026-08-14-gongchuang-signed-policy-gate.md) | 中文

## 问题

共创企业助手不能在更换 DeepSeek、OpenCode 或自定义 API 后退化为通用聊天。高企写作、企业数字身份证、政策核验、同行对标、评分、体检、报告和去 AI 味都已在 V1.6.6 中定义事实边界、计算口径、结构和校验。仅把 `SKILL.md` 放入模型上下文仍会依赖模型自觉。

## 决策

客户端和技能套件保留相互独立的版本：客户端为 `V0.1`，内置技能套件为 `V1.6.6`。签名桌面宿主持有进程，只发布受控 Cordis 组合，并向私有 `@gongchuang/client-policy-gate` 包提供逐字节签名的 Ed25519 策略信封。

原生插件在加载时同步验证签名和产品身份。宿主等待 `agent/pre-step` waterfall，在首个请求之前拦截所有提供方。`tools/pre-execute` waterfall 依次执行拒绝优先、询问其次、允许最后的匹配，默认拒绝；除非签名策略明确允许，否则拒绝无法归属来源的调用，并保留下游更严格的决定。信封缺失、畸形、遭篡改或版本漂移时一律关闭失败。

除了签名清单，插件代码也会固定三类产品模型提供方、默认拒绝无归属工具的规则、产品必需工具、原始命令禁用项、专业回执及四种正式文件回执身份。有效签名不能授权一份更弱的 V0.1 策略。原始 Shell、PowerShell、终端、后台任务、子代理和工作流工具直接拒绝；浏览器和计算机自动化仍须用户确认。

兼容 hook 只作为迁移适配器，不属于信任边界。生产宿主必须让门禁不可移除，并让文件系统、进程、浏览器、网络和第三方插件操作全部经过同一个 broker。

桌面宿主验证技能包的逐文件 Ed25519 索引，再把包内 `delivery-contracts.json` 和 `skill-call-graph.json` 的不可写路径传给门禁。门禁按用户原始任务选择专业技能，递归展开 `requires` 和 `quality_gate` 关系，并只在 `skill` 工具真实成功返回后记录激活。任务主技能决定正文结构和任务专属主体检查；支持依赖只贡献其事实与来源校验，不得重新分类交付物。当前轮次缺技能、缺必需输出标记或缺受信任交付回执时，宿主追加纠正消息并继续同一轮，不允许模型直接结束。

`@gongchuang/signed-skill-runtime` 是技能包脚本唯一可由模型调用的进程路径。其工具只接受操作标识和封闭的结构化参数，不接受命令或脚本路径。宿主在每次调用时重新核对已签名操作清单、所属技能的全部文件、内置 Python 可执行文件、工作区边界、净化环境、无网络沙箱、超时、输出上限与已声明退出码；操作还必须绑定同一轮已经激活的所属技能。

宿主按照真实调用 ID 和宿主计算的 SHA-256，记录本轮成功完成的受信任读取、搜索、抓取及固定 MCP 工具输出。模型声明为 `verified` 的每条证据都必须绑定其中一条记录；声明的取值和网址必须实际出现在该输出中，用户提供的取值则必须出现在本轮用户输入中。这能阻止模型自行生成一条带核验外观的来源，但不能证明来源权威，也不能证明自然语言结论必然由来源语义推出；专业可接受性仍由当前技能中的来源选择、计算、冲突处理和复核规则决定。

正式交付既可以由提示词触发，也可以由路径类工具参数中的正式文件扩展名触发。专业校验内核绑定提取正文与文件摘要；后续每次文件改写都会清空全部正文相关回执，轮次结束前还会重新打开并计算文件哈希。V0.1 每轮只接受一个正式文件路径，使每个文件分别取得专业、可打开性、正文、品牌和逐页视觉回执。

## 后果

专业规则对 DeepSeek、OpenCode 和自定义 API 使用同一执行链。高企创新能力四栏缺失、已核验证据未绑定、正式文件沿用旧回执、去 AI 味后未做一致性复核等问题会在轮次层被阻止。但 Word、PDF、PPT 和 Excel 的真实内容、可打开性、品牌和逐页视觉回执仍需受信任生产工具。技能包内签名脚本通过宿主持有的受限运行器执行，普通命令执行仍不可用；代码签名、公证、升级回滚和全新设备验收仍是发布门禁。

## 曾考虑的替代方案

**仅依赖提示词约束。** 不采用，因为它只具有建议性，并且依赖模型遵守。

**把 Codex 或 Claude 兼容 hook 作为主要边界。** 不采用，因为它们只覆盖部分生命周期，专门路径仍可能绕过。

**异步、游离的会话启动验证。** 不采用，因为它可能错过首个请求。

**工具匹配默认允许。** 不采用，因为新安装的第三方工具可能逃过审查。

**只使用操作系统凭据库而不禁止命令执行。** 不采用，因为同一已登录用户下运行的任意进程仍可能调用平台凭据 API。
