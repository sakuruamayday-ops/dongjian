# Agent Note: DeepSeek Harness alpha.3 后的共创职责边界

Status: implemented

[English](2026-09-01-gongchuang-alpha3-ownership.md) | 中文

## 问题

共创在 DeepSeek Harness 之上提供企业自动化、中转模型连接、账号、附件、签名技能和桌面更新。Harness 新版本可能增加名称相似但只覆盖部分产品契约的行为。两套实现并存会形成相互竞争的所有者，仅按名称删除产品实现则会破坏仍在使用的消费方。

## 决策

V0.4.0 打包不可变 Harness 标签 `dsh-v0.1.2-alpha.3`，对应提交 `dd6322d604e00eec1ba5e0c8541159906a21094a`。这是当前客户端版本的基座，不是永久基座。后续每个客户端版本审计当时最新的官方 Harness 发行；其公开行为能够完成集成和验证时继续升级。单个客户端版本只打包一套 Harness 基座。

物理连接恢复、Remote 传输失败、会话读侧投影、已加载轮次导航、提示内容准入、steer 与 follow-up 图片交付、延迟语法高亮、通用 Windows 原子替换、有界流队列、单轮令牌与耗时统计以及 JSONL 会话持久化由 Harness 负责。共创不保留这些职责的第二套实现。产品会话组合原本就使用 JSONL，因此 alpha.3 移除未使用的上游 SQLite 会话后端不需要迁移用户数据。产品图记忆使用的 SQLite 是另一套独立存储，保持不变。

产品继续保留 `@gongchuang/local-automation`、模型连接、账号与操作系统凭据、企业空间与附件、签名技能与策略、面向用户的错误脱敏、模型费用投影和桌面更新。alpha.3 没有提供这些产品契约：持久任务结果对话、已确认的提供方目录与刷新策略、设备绑定登录、企业删除与草稿引用、Ed25519 准入、中文诊断指引、目录价费用投影，以及签名绑定的多平台安装。

上游 Schedule 仍是会话内提醒能力，不作为共创自动化的持久化或执行后端。上游通用模型设置继续作为第二产品入口禁用；产品适配层消费共享模型目录和 Remote API。Electron 打包直接根据最终 `app.asar` 校验 DeepSeek 与共创工作区包的必需 peer；开发工作区能够解析依赖不属于制品证据。

职责判断以行为为准。只有官方公开接口、失败语义、持久化生命周期和打包设备测试覆盖全部活跃消费方，才移除产品实现。设计参考和相似名称都不足以授权替换。满足该判断时优先采用官方实现；产品代码只为官方尚未覆盖的当前契约保留。

## 考虑过的替代方案

- V0.4.0 停留在 alpha.2。未采用，因为 alpha.3 已提供可靠的提示内容与图片准入、已加载轮次投影、延迟高亮和当前 JSONL 单一会话面。
- 保留 alpha.3 官方行为的产品重复实现。未采用，因为两个所有者可能在事件顺序、重试生命周期、渲染和持久化上产生分歧。
- 删除所有名称与上游功能相似的共创包。未采用，因为保留的产品契约仍有活跃消费方，官方也没有等价能力。

## 后果

alpha.2 制品和回执不能证明 alpha.3 候选。V0.4.0 从冻结的 alpha.3 源提交重新形成测试、打包闭包、旧会话打开与写回重开、macOS arm64 与 x64 生命周期、Windows 验收、文档渲染、直接更新和公网发布证据。

产品保持一套 Harness 运行时加产品适配层，不形成另一套传输或持久化分叉。后续 Harness 升级在移除产品代码前重复同一职责审计。

## 测试

合并需通过 Remote 与 Controller、提示词与图片准入、会话投影与轮次导航、产品模型、账号、自动化、企业空间和附件测试，完整 Host 与 Client 类型检查，最终归档工作区 peer 闭包、精确安装包启动、V0.3.3 介质恢复及平台发布矩阵。浏览器测试通过 `data-app-frame` 定位应用外壳；官方轮次导航也提供 `frame` 类后，CSS Module 名称片段不再属于稳定选择器。源码构建通过不能证明 Electron 打包补丁可以移除，也不能证明可下载应用已经具备发布条件。
