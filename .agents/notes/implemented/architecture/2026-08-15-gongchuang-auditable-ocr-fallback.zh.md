# Agent Note：共创可审计 OCR 回退

Status: implemented

[English](2026-08-15-gongchuang-auditable-ocr-fallback.md) | 中文

## 问题

DeepSeek 的 V0.1 路由只支持文字输入，而企业工作中经常出现扫描件、截图、长聊天记录和纯图片 PDF。把这些字节交给纯文本模型，要么直接失败，要么诱使模型猜测。安装任意视觉插件会增加第二个远程模型端点、运行时可变的软件包解析，以及一条宽泛的视觉解释路径，不适合处理政策数字、企业名称、日期和知识产权状态。

最初的 PaddleOCR 连接器还会在首次使用时执行 `uvx --from paddleocr-mcp`。该命令通过 `PATH` 与网络在运行时解析软件包内容，不属于桌面候选安装包的签名文件树。直接上传长图还可能超过服务限制；中间切片失败后重试会重复上传全部已完成切片，也没有可供审计的源图身份。

## 决策

V0.1 使用 PaddleOCR 官方 MCP 的 AI Studio 模式，作为用户主动启用的 OCR 回退。它只提取文字，不承担通用视觉理解：图表趋势、空间关系、颜色、物体和从外观推断的状态均不属于证据边界。连接界面必须披露，启用后图片切片会离开设备并发送到百度官方服务；产品不得把它描述成本地推理。

产品运行时内置经过审核的 `paddleocr-mcp` 0.8.5。运行时分阶段构建与启动验签要求签名 Python 树内恰好存在一份 `paddleocr_mcp/__main__.py` 和匹配的发行元数据。连接器使用已经核验的绝对 Python 路径与固定参数 `-B -E -s -m paddleocr_mcp` 启动该模块，不调用 `uvx`，不在首次使用时下载代码，也不回退到 `PATH`。

长截图在上传前先于本机处理。超过固定高度和纵横比阈值的图片只为行能量分析而缩小，在受限尺寸窗口内优先选择低内容横线作为切点，再按原始分辨率带少量重叠裁切。每张源图与每个切片都有 SHA-256 身份。合并时最多只删除 24 行完全一致的规范化边界重叠；明确禁止模糊匹配，因为一个字符差异就可能改变政策事实。进程内最多保留 64 个成功切片的文字结果，使重试能够续用已完成切片；连接器服务停止时清空，绝不持久化。持久会话中的回退说明会记录源图摘要、切片数与复用数，并同时保留能力限制。

## 测试

单元测试证明普通图片保持原始字节，长图生成带摘要的受限重叠 PNG 切片，完全重复的边界会删除，而近似政策事实不会被合并。连接器测试证明重复图片会复用成功切片、输出审计摘要，且凭据值不会外泄。产品运行时测试证明缺失模块或未经审核的发行版本不能被提升，完整签名文件树可以验收，并且连接器命令使用签名 Python 路径而不是 `uvx`。客户端测试证明远程数据披露会在配置前显示、用户必须明确同意，并且 Host 工具发现失败时界面不能显示已就绪。Windows 与 macOS 候选验收仍必须在安装后使用真实 OCR 样图完成冒烟测试。

## 考虑过的替代方案

**把完整第三方视觉工具包设为默认。** V0.1 否决，因为其 OCR 本质上是远程视觉模型推理，不是确定性的本地 OCR，并会增加另一套凭据、数据接收方、模型行为和插件供应链。其有价值的工程思路，包括智能切片、切片身份、断点续跑和保守合并，已在产品边界内吸收。

**打包完整的本地 PaddlePaddle 推理。** 延后。它能让图片留在设备内，但会显著增加平台运行时体积、冷启动时间、模型分发和 Windows/macOS 兼容工作。未来可以增加经审核的本地来源，而不改变图片文字证据边界。

**使用模糊 OCR 行去重。** 否决，因为政策编号、金额、日期和企业名称可能只差一个字符。可以容忍重复行保留，但绝不能只因相似而静默删除事实。

## 后果

纯文本模型收到的是明确 OCR 证据，而不是猜测视觉；重试成本降低，同时不会形成第二套持久企业数据存储。由于 Python 运行时必须携带经审核的 MCP 软件包与依赖，签名安装包会更大。OCR 仍不能证明非文字视觉事实，AI Studio 模式的外部数据边界必须在授权前由连接界面和隐私说明清楚展示。
