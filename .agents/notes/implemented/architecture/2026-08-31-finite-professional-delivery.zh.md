# Agent Note: 有限专业交付与版本化合同

Status: implemented

[English](2026-08-31-finite-professional-delivery.md) | 中文

## 问题

当前专业校验器会把普通文档缺陷转换为整轮不得结束的条件。缺少章节、证据源不可用、用户取消授权，或者文件已经生成后才发现不一致，都可能反复引导同一 Agent 修改直至通过。这混淆了产品质量分级与基础设施故障，使用户取消失效，也让已经形成的草稿无限运行。

技能套件还拥有大量模板和数据源流程。没有版本化合同，同一要求可能被不同模型作不同解释，Skill 更新可能在任务进行中改变规则，模板也可能在没有经过真实回填、重开和打包运行时渲染的情况下进入正式发布。

## 决策

每次专业修订绑定一份机器可读交付合同版本和一个交付画像。画像要求使用稳定标识，并明确分为 `critical` 关键要求和 `advisory` 建议要求。由确定性校验器而不是模型赋予四种有限状态之一：

- `formal`：所有关键要求通过；建议问题保留为可见诊断。
- `draft`：仍缺一个或多个关键要求，但答案或文件可作为草稿使用。
- `waiting-user`：下一步需要用户补充证据、完成授权或作出选择。
- `failed`：解析器、签名边界、持久化层或其他基础设施无法安全地产生草稿。

普通合同问题不得仅为维持本轮运行而抛出异常。一次修订最多执行一次由合同唯一确定且不补造事实的修复。再次校验仍为 `draft` 时，结束当前执行并等待用户发起新的修订。待完善文件同时具有文件名标识、产品卡片标识和本地结构化诊断；没有重新校验通过，不能改称正式产物。

任务持久化合同版本、阶段、检查点、已确认事实、已尝试数据源和终态。重启后未完成工作保持暂停，用户继续时从检查点恢复，不静默升级合同，也不重复已经完成的采集。旧客户端继续使用最后一个兼容的正式 Skill，旧任务在当前修订中保留启动时合同。

企业数据采集采用有限顺序降级：天眼查、企查查、本地可核验材料、政府官方来源。瞬时故障最多重试一次；用户取消鉴权、额度拒绝、工具不支持或提供方缺失时立即跳到下一来源。关键事实仍缺失时形成待完善稿，非关键事实保留“未核验”标识。

正式模板源统一使用 DOCX、XLSX、PPTX 等稳定现代格式。用户输入仍可使用任意扩展名，但只有内容解析成功后才声明支持。每次含模板的 Skill 发布，对全部模板执行清单和静态解析，对变更或被引用模板执行合成回填、重开、占位符扫描和渲染检查；当前模板清单还需先完成一次同等深度的基线。模板失败只阻止 Skill 候选激活，不影响已安装兼容 Skill 或用户当前任务。

## 考虑过的替代方案

- 取消校验，完全依赖模型指令。未采用，因为模板结构、证据存在性和正式身份属于确定性产品主张。
- 保留校验器，只提高轮次或时间上限。未采用，因为更大的上限仍会把质量问题变成延迟失败并重复消耗。
- 发现第一个问题立即停止。未采用，因为合同唯一决定的机械修正成本低且安全；一次有界修复能够提高可用完成率而不隐藏不确定性。
- 把所有要求都设为关键。未采用，因为可选政策展开或偏好章节布局不应阻止其他方面合格的交付物取得正确身份。

## 后果

正式身份继续严格，但普通用户任务总能进入可见状态。Skill 必须明确决定要求关键性并保持稳定标识。历史产物不重新分级。模板发布检查进入 Skill 激活流程，打包客户端则在 macOS 和 Windows 证明解析与渲染闭包。

## 测试

故障矩阵覆盖全部交付画像的缺章节、缺证据、较晚依赖、重复问题、数据源超时、授权取消、工具不支持、校验器故障、用户取消、进程退出、重启和合同升级。每种情况必须在有限步骤内进入 `formal`、`draft`、`waiting-user` 或 `failed`，同一次修订的轨迹中不得出现超过一次确定性修复。
