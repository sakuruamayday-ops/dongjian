# Agent Note：部署锁定的 Agent Preset 名单

Status: implemented

[English](2026-08-15-deployment-locked-agent-preset-roster.md) | 中文

## 问题

Agent preset 决定模型可见的提示词与工具目录，因此切换 preset 是一次能力变更，而不是视觉偏好。`includeUserRoot: false` 能阻止部署发现用户编写的 preset，却不能限制共享随附根目录中哪些目录可被选择。一个复用 DSH 随附根目录的桌面产品即使默认使用已审核 preset，仍可能把旁边的编码、终端、子代理与 Cordis 编写 preset 列出并解析出来。

工具分发策略仍会拒绝禁用调用，但模型会收到无关 schema 和编码指导，把上下文浪费在注定失败的调用上，也可能在一个没有描述产品专业证据规则的提示词下开始会话。旧的 `agent-presets.default` 设置还可能选择产品并未打算暴露的 preset。

## 决策

`dsh-agent-presets` 增加可选的部署方 `allowedIds` 名单。配置后，名单必须非空、包含互不重复的有效 preset id，并包含部署配置的 `default`。`list()` 在每次解析与编写操作之前过滤发现结果，因此不允许的 id 不能被列出、解析、读取、复制、删除、挂载、重新组装，也不能用于宿主常驻视图。保存的默认值如果不在名单内，就退回部署默认值；普通 DSH 应用不设置 `allowedIds`，原有可扩展行为不变。

共创企业助手把精确名单锁定为 `gongchuang`。该 preset 包含专业身份、受沙箱约束的文件工具、已签名 V1.6.6 技能根目录、联网检索与上下文压缩；明确不包含 Shell 与 PowerShell、后台任务、计划与目标、Todo、用户编写指令、子代理、工作流、Cordis 编写和任意原生插件装载。宿主准入同时钉住默认值、单项名单与关闭的用户根目录；签名工具分发策略仍作为独立执行层，约束所有从全局层可见的工具。

## 测试

Agent preset 包测试证明无效名单会在构造时失败，不允许的 preset 会从发现和显式解析中消失，旧的用户默认值会退回已配置的允许默认值。随附 Web 组装会挂载 `gongchuang`，断言其精确的模型工具目录与身份提示，并证明终端、委派、工作流、目标、Todo 和 Cordis 编写工具均不存在。产品宿主准入测试会拒绝可写根目录、不同默认值或扩大的名单。

## 考虑过的替代方案

**只设置 `includeUserRoot: false`。** 否决，因为共享系统根目录仍包含 DSH 的全部随附 preset。

**保留全部 preset，只依赖签名分发门禁。** 否决，因为被拒工具和不匹配的提示段仍会消耗模型上下文并制造确定性失败路径。分发策略仍然必要，但它是最后一道边界，不应代替工具目录设计。

**另打包一个只含单个复制目录的实体 preset 根。** 否决，因为这会复制一套应用资产并产生漂移。精确逻辑名单允许部署继续共享不可变应用根目录，同时只选择已审核子集。

## 后果

产品会话拥有稳定的专业提示词与更小的工具前缀，有利于缓存稳定并减少模型漂移。不允许的目录仍可能作为普通 DSH 资产存在于磁盘上，但不属于锁定部署的能力。使用 `allowedIds` 的部署在受信组装同步更新名单之前，不能编写并启用新 preset；这一步有意设置的审核成本，正是封闭产品名单的代价。
