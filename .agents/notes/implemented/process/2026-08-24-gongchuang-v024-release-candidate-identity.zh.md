# Agent Note: 共创 V0.2.4 发布候选身份

Status: implemented

[English](2026-08-24-gongchuang-v024-release-candidate-identity.md) | 中文

## 问题

桌面包和产品常量此前仍携带生产版本号，而源码已经包含新的用户可见行为。新产物继续复用生产身份会使更新比较和发布证据无法区分，但在部署前先改写生产记录又会把尚未发布的构建误报为当前版本。

## 决策

产品清单独立记录两个事实。`productionBaseline` 在生产事务完成前继续保留已验证的 V0.2.3，包括其源码提交和服务器 release id；`client` 及全部打包版本来源统一标识新的 V0.2.4 候选。契约测试要求保持这种区分，并要求桌面包、应用常量、策略和验收脚本跟随候选身份。

V0.2.4 macOS 产物在部署前完成本机 arm64 和 Rosetta x64 验收。验收使用隔离安装与用户数据位置；证据归档后，临时应用、挂载镜像、用户数据和演练目录移入 macOS 废纸篓。Windows 产物按主人确认的未签名风险例外，在架构和包内完整性静态验收后发布；不要求发布前 Windows 真机回执，设备反馈在发布后记录。

服务器事务成功后，发布证据提供不可变的 V0.2.4 源码提交和服务器 release id，再由后续元数据提交推进 `productionBaseline`。GitHub 安装资产不属于本次发布权威。

## 曾考虑的替代方案

**打包前把 `productionBaseline` 改为 V0.2.4。**不采用，因为服务器尚未接受任何 V0.2.4 产物时，这会抹去准确的当前生产事实。

**部署前所有包继续使用 V0.2.3。**不采用，因为更新器会把实质不同的产物当作既有版本，无法建立唯一候选身份。

**等待 Windows 真机回执。**主人已明确取消本版前置要求；静态产物证据和未签名风险披露仍为必需项。

## 后果

三平台候选使用同一语义版本，准备期间的生产元数据仍保持真实。发布后推进生产基线只是证据回填，不是第二次客户端发布。本机 Mac 验收不再遗留已安装测试应用或临时用户数据。
