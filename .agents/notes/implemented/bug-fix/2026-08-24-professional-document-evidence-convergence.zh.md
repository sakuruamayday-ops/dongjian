# Agent Note：专业文档证据按显示值收敛

Status: implemented

[English](2026-08-24-professional-document-evidence-convergence.md) | 中文

## 问题

一次真实 Windows 表格任务暴露出四个相互放大的问题。桌面导入允许旧式 `.xls`，但签名文档提取器和随包 Python 运行时不支持；XLSX 正式文件按原始 OOXML 提取，导致共享字符串索引和百分比存储值进入数字证据，而不是用户看到的单元格值；标准号、手机号和身份证号也被当成业务数量。与此同时，经不可见签名操作生成的专业文件可能没有激活可打开性回执，退出码为零但只输出警告的操作也可能冒充提取成功。

这些问题会让模型临时安装依赖、改写文档并逐个补内部数字，最后仍可能在没有证明文件可打开时发布。

## 决策

- 签名提取器新增 `.xls`，三平台产品运行时固定 `xlrd 2.0.2`；XLS 和 XLSX 都输出显示百分比与日期。
- XLSX 正式文件解析工作簿关系、共享字符串、富文本、单元格样式、百分比和日期，不再把内部索引当作文档事实。
- 数字事实排除可识别的标准号、手机号和身份证号；百分比显示符号按数值等价绑定，其他业务数量仍须证据或计算。
- 企业画像主体锚定与高企四栏完整合同只适用于正式回答深度，明确限定的问题保持单点或分析深度。
- 签名操作可声明一个 stdout schema 版本；运行时只接受精确 JSON 对象和匹配版本，退出码为零也不能让警告或前缀文本通过。
- 专业文件绑定时激活正式回执，真实文件未完成可打开性探测前禁止发布。

## 备选方案

**每次任务临时安装缺失的 Python 依赖。** 这会让相同文档的处理依赖网络和可变的用户环境，并在每台设备上重复付出安装成本，因此改为在签名产品运行时内固定受支持的提取依赖。

**继续绑定原始 OOXML 令牌，再用提示词逐项修补不匹配。** 共享字符串索引、百分比存储值和依赖样式的日期是实现细节，不是文档事实。提示词补丁会保留错误语义并持续造成修复循环。

**提取或可打开性证据缺失时仍允许发布。** 这会让退出码为零的警告输出或不可读文件成为成功的正式交付。现有失败关闭边界继续保留，并由真实专业文件激活。

## 影响

支持路径不再要求用户在任务中临时安装 `xlrd` 或 `pdfplumber`，Excel 证据使用可见单元格语义。标准和个人标识不再造成无关的数字修复循环。普通问答收窄没有弱化正式交付的证据、签名、文件身份、品牌、视觉、权限和回滚措施。

## 验证

定向测试覆盖真实 BIFF8 XLS、XLSX 共享字符串和样式百分比、非日期格式 `[Red]0`、百分比数值等价、标准号和个人标识排除、限定企业画像与高企校验、结构化 stdout 成功与失败、文件探测前发布拒绝。产品真实 Loader 组合与完整发布测试负责装配路径验收。
