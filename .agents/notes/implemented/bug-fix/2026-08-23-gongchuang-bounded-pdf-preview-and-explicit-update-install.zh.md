# Agent Note: 共创 PDF 预览内存上限与显式更新安装

Status: implemented

[English](2026-08-23-gongchuang-bounded-pdf-preview-and-explicit-update-install.md) | 中文

## 问题

桌面 PDF 渲染器最多保留 32 组完整的逐页 PNG，但没有字节上限；PyMuPDF 比较请求还会把其中一组暂时复制为 base64 和 JSON。包含大量高图像页面的文档会因此按内容大小消耗内存，而不受产品上限约束。Windows 更新器在下载后仍启用 electron-updater 的退出时安装。当 Host 无法在安装前关闭活动工作时，控制器会报告下载失败，但之后一次普通退出仍可能安装该更新。

## 决策

渲染器把单份同源预览限制为 32 MiB，内存预览缓存限制为 64 MiB 和 32 条记录。逐页捕获时即拒绝超限预览，接收新的有界记录前淘汰最旧记录，并在自动比较开始时消耗匹配记录。PDF 字节、页数、源正文一致性、输出摘要和逐页比较仍是必需验证。

桌面更新器禁用 `autoInstallOnAppQuit`。下载失败会清除待安装状态，下载成功则保留该状态。Host 安装前关闭失败时返回独立的准备错误，不调用 `quitAndInstall`，且只能通过再次显式安装操作继续。兼容安装入口使用相同的准备失败处理。关闭完成后由主进程交接流程负责恢复：electron-updater 拒绝 `quitAndInstall`、macOS 安装助手启动失败，或任一控制器返回安装错误时，Electron 会先重新启动磁盘上未变更的当前应用，再退出已经停止运行时的进程。

## 曾考虑的替代方案

**只保留 32 条记录数限制。**不予采用，因为记录数无法限制 PNG 字节或 base64 序列化内存。

**把源预览写入不受管理的临时目录。**不予采用，因为该方案会增加文件生命周期和清理义务，当前源预览比较可以保持在经测量的内存上限内。

**把退出时安装保留为恢复路径。**不予采用，因为产品报告安装准备失败后，更新不得在之后一次无关退出中安装。

## 后果

超过预览上限的高图像 HTML 会在生成视觉通过回执前失败，必须减少内容或拆分文档。已消耗的预览不能在不重新导出的情况下对同一 PDF 再次执行。已下载的 Windows 更新可在不重复联网下载的情况下重试，但只有显式触发的安装前关闭成功并调用 `quitAndInstall` 后才会安装。原生交接失败会短暂重启当前版本，避免窗口继续连接已经停止的 Host 运行时。关闭操作本身被拒绝时不视为已经完成，也不会触发该重启路径。

## 测试

桌面测试固定两级字节上限和预览消耗行为，区分下载失败与安装前失败，要求 `autoInstallOnAppQuit` 始终为 false，并证明准备失败既不调用 `quitAndInstall`，也不丢弃已下载的重试状态。交接测试覆盖关闭后控制器返回错误和原生调用抛错，并证明关闭本身未完成时不会重启。
