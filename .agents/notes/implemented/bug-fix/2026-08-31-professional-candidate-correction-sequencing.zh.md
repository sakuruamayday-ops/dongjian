# Agent Note: 专业候选正文纠正顺序

Status: implemented

[English](2026-08-31-professional-candidate-correction-sequencing.md) | 中文

## 问题

专业正文内容校验与执行链闭合是两项独立检查。校验通过后激活的技能可能继续展开必需依赖，此时已通过候选仍然有效，但技能激活集尚未闭合。轮次停止过去会同时提示激活缺口与最终正文不一致，并在每次停止时附带完整候选正文。模型因此容易在补技能与重复发送正文之间来回切换，既增加上下文，又没有先解决缺失激活。

## 决策

策略门禁按固定顺序处理较晚展开的依赖与最终候选对账。聊天候选已经通过时，只要仍有必需技能未激活，轮次停止就明确正文内容校验已完成，把规范化候选保留在 Host 状态中，只输出字符数、SHA-256 和缺失技能。所有必需技能在同一轮真实成功激活前，不执行候选对账。

激活闭合后，逐字对账继续关闭失败。同一候选摘要首次不一致时可以附带一次完整保留正文，供模型精确恢复；该摘要之后的停止只给简短复用指令。新校验通过的不同摘要可以重新获得一次完整纠正。既有无进展次数与累计纠正上限继续把未解决轮次收敛为无成功回执的未完成结果。

依赖通知只列出确实尚未激活的技能。调用图展开或正文校验回执都不能替代激活；只有 `skill` 工具真实成功返回才记录激活。

## 曾考虑的替代方案

**自动把新展开依赖标为已激活。** 不采用，因为调用图成员关系不能证明模型已加载并遵循技能，而且会弱化执行链不变量。

**缺依赖时仍对账并附带候选正文。** 不采用，因为同一条纠正会给出两个相互竞争的下一步，还会重复已经通过内容校验的正文。

**候选不一致时完全不再附带已通过正文。** 不采用，因为首次精确恢复会依赖模型从较早上下文重建空白与标点。每个摘要只展开一次，既保留确定性恢复，也避免重复载荷。

## 后果

较晚展开依赖时，纠正步骤短且目标唯一，并保留已通过正文检查点。候选逐字一致、证据、回执和产物检查都没有放宽。同一不一致重复发生时消耗的 token 明显减少，未解决的激活或正文漂移仍会进入既有有界未完成结果。
