# Agent Note: 生产版本基线与源码历史恢复

Status: implemented

[English](2026-08-24-production-baseline-source-recovery.md) | 中文

## 问题

生产回执与制品将 `cf827c8624…` 标记为 V0.2.3 发布源，但规范审查仓库仍对外投影 V0.1.4 包与清单身份，也无法解析该源对象。GitHub main 停在 V0.2.3 发布链之前，因此正确的二进制发布无法从所声明的源码仓库复现。

## 决策

将精确发布源对象恢复到 `gongchuang/main`。规范中文文档分支与发布链通过双父提交合流，不丢弃任一方历史。`product-manifest.json` 拥有机器可读 `productionBaseline`，包含客户端 0.2.3、formal 技能 1.6.9、RC.2 提交 `b150a551…`、发布源 `cf827c8624…` 和服务器 release id 6。契约测试将桌面包、包常量和产品常量与该基线比较，不再另维护一个硬编码版本字符串。

## 曾考虑的替代方案

**只修改文档展示文字。**不采用，因为发布源对象仍会缺失，未来构建也无法恢复发布。

**重建并重发 V0.2.3。**不采用，因为现有生产制品与更新清单已经一致，缺陷位于仓库历史和版本消费。

**把未提交的下一候选命名为 V0.2.4。**不采用，因为尚无版本决定、制品或发布事务。

## 后果

远程仓库可解析已发布 V0.2.3 源，当前产品消费方共用一个生产基线，分叉的中文文档历史也得到保留。该修复不创建 GitHub Release、不部署服务器、不切换更新源，也不需重发 V0.2.3。未来候选的版本号仍是显式发布决定。
