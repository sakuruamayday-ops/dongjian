# Agent Note: 共创 macOS 签名更新断点续传

Status: implemented

[English](2026-08-29-gongchuang-signed-macos-update-resume.md) | 中文

## 问题

自管理 macOS 更新器会把每个签名应用归档下载到随机事务目录。客户端在慢速传输中退出后，后续启动无法识别或复用已经下载的字节，设置页也只显示无法判断进度的忙碌状态。原有本机发布演练完成过快，没有覆盖中断、重启、HTTP 范围语义和有用的进度显示。替换应用包还必须与 Electron 用户数据目录和 macOS 钥匙串中的账号凭据保持独立。

## 决策

未完成归档保存在稳定目录中，目录身份由精确签名清单的 SHA-256 以及所选产物的 URL、架构、文件名、大小和 SHA-256 共同派生。可续传状态文件重复记录该签名身份，并保存强 `ETag` 或有效 `Last-Modified`。后续控制器先对本地已有前缀重新计算哈希，再发送 `Range` 与 `If-Range`；只有 `206`、`Content-Range`、`Content-Length`、恒等内容编码、响应 URL 和校验器均与该前缀精确一致时才接受响应。完整字节在解压和应用验证前仍须满足签名清单中的总大小和 SHA-256。

服务器没有可用校验器时仍可返回完整 `200` 下载。该传输继续执行相同的最终大小和 SHA-256 验证，但中断前缀不会被展示或复用为可续传内容。范围请求若返回完整 `200`，更新器会废止旧前缀，并从第零字节验证完整替代响应。

归档写入器会在打开、传输、背压和结束的完整生命周期内持续接管错误。异步磁盘故障会因此使受控下载失败，并且只保留受校验器约束的前缀，而不会终止 Electron 主进程。安装助手只能在运行时关闭成功后启动，主进程也只能在助手启动成功后退出；运行时关闭失败时，不会留下一个等待后续普通退出后提交更新的助手。

主进程把有界下载进度投递给渲染器。设置页显示百分比、预计剩余分钟、验证阶段以及是否沿用上次字节。可续传下载中断后会恢复为“继续更新”，进程重启后的启动检查也会恢复同一操作。客户端不会在启动时静默续传并安装，因为再次明确点击可以维持现有用户决定，避免更新在未确认时关闭正在运行的任务。

更新助手只替换已验证应用旁边的 `.app` 目录。Electron 用户数据、加密凭据文件、钥匙串内容、账号令牌、已保存用户名和密码、设备身份、对话及企业文件均不属于该替换事务。正常运行时关闭只会关闭凭据后端，不会调用账号退出或移除已保存凭据。

## 验证

macOS 更新器测试驱动受限速流在写入前缀后失败，再用同一用户数据目录创建新控制器；测试先拒绝错误 `Content-Range`，随后以精确 `Range` 和 `If-Range` 从记录偏移完成下载，并验证最终签名摘要、进度续传偏移和助手交接。没有校验器的完整响应仍可接受。回归用例注入异步 `ENOSPC` 写入故障和运行时关闭故障；两者都会返回受控错误，后者还证明助手没有启动。一项单元测试证明更新器不会在下载、暂存、验证和助手准备过程中删除 Electron 用户数据目录下的凭据存储文件。该测试没有调用 `safeStorage`，也不能证明跨版本钥匙串访问或自动登录；这些仍待打包应用的真实设备生命周期实测。渲染器测试观察继续更新操作、实时百分比和剩余时间文本。

## 备选方案

**每次都从第零字节重新下载。** 未采用，因为慢速或不稳定网络会反复丢弃数百兆字节，即使签名产物和服务器表示都没有变化。

**只按文件名和本地长度续传。** 未采用，因为相同文件名或版本标签不能证明签名清单、产物摘要、架构、URL 或服务器表示没有变化。

**客户端启动后立即自动续传并安装。** 未采用，因为下载完成会触发运行时关闭和应用替换。跨启动持久化该副作用会绕过明确更新操作，并可能中断新工作。

**所有更新都强制要求校验器。** 未采用，因为校验器是安全复用前缀的必要条件，不是完整签名下载的必要条件；完整响应仍会验证最终大小与 SHA-256。没有校验器的服务器继续兼容完整下载。

## 影响

中断传输可以继续，且不会削弱清单、归档、运行时、技能、架构或应用验证。下载进度变得可见，客户端重启后会提供明确的继续操作。续传请求前会增加一次本地前缀顺序读取；服务器变更或省略表示校验器时，精确 HTTP 检查可能废止已有前缀。用户重新打开客户端后仍需确认一次继续更新，已保存登录材料则始终位于应用替换生命周期之外。
