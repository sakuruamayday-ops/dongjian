# Agent Note: 产品文件操作与交互状态

Status: implemented

[English](2026-09-03-product-file-actions-and-interaction-state.md) | 中文

## 问题

产品需要容易识别的文档操作和稳定的来源引用。原生打开成功并不能单独证明文件名、文件类型、应用菜单或注释来源可用。已允许的自动任务如果在 Cordis `inject` 声明中漏掉兄弟服务，也可能在模型执行前失败。

## 决定

共享 `FileCard` 组件展示完整文件名、文件类型和可选质量状态，产品只提供有界原生操作。桌面主进程验证调用来源，并把每个文件解析到已选择工作区内，再列出已安装应用、指定应用打开、在文件管理器显示或复制文件。macOS 的应用身份由 LaunchServices 提供，Windows 由系统选择器决定打开应用。复制不会覆盖已有文档。

产品从现有持久用户展示元数据和当前草稿中派生来源消息的注释标记，消费事件窗口增量，并向 Chat 的带键 hook 暴露按消息稳定的可观察状态。选区末端位于未选中的零偏移位置时，可视为属于前一段已选文字；真正跨消息的选区仍被排除。

注释意图使用当前评论和消息正文，并排除被引用的历史。没有肯定性分析或创建要求的纯转录不进入专业路由。明确否定的继续执行和工具调用不会恢复较早任务；真实专业指令继续遵守相同的校验和权限要求。

交付通知只在模型步骤边界发布。工具完成 hook 会持久化检查点，但不会在对应工具结果之前插入用户消息，因此要求工具交换连续的提供方可以消费已完成的文件检查而不触发协议级 400。不会删除任何工具结果或历史消息。

原生 B04 复测还在恢复旧存储交换时复现了 400。LLM 适配器投影仅在一组匹配工具结果完整之后延迟插件文本通知；用户消息和不完整交换保持不变，消息身份与内容得到保留，已存历史不被重写。

混合 PDF 运行多次漏传外层 PTC 展示说明，并截断加载后的技能内容。`run_code` 会给缺失或空白展示标签提供默认值，同时保留代码和嵌套参数校验。成功加载的嵌套技能通过现有附加上下文队列贡献完整渲染指令。是否改善真实流程由原生证据判断，不增加新的阻塞校验器。

下一次 PDF 原生运行完全跳过读取技能并自行拼接提取脚本。Office/PDF 附件提示现在明确内置读取器及其真实相对路径参数，纯文本保持不变。这是模型上下文，不是新的交付前置。

后续运行使用了读取器，但 OCR 包装器没有页码选择参数，模型仍需自行生成临时 PDF。`workspace_pdf` 现在接收读取器的一页起算页码列表，使用已核验的内置 PyMuPDF 在内存中选页，按源文件与页码列表缓存并返回原页来源。源 PDF 不变，非法、加密或越界页码不会进入 OCR。另一次原生业务运行还发现相对发布路径错误地从桌面进程当前目录 `/` 解析，而不是从会话目录解析；文件发布改为按该会话解析相对路径，并拒绝没有会话归属的相对路径。

一次数字化任务在明确禁止删除的情况下执行了 `cd /tmp && rm -rf digpre`。现有调度前策略会拒绝直接的 Bash 和 PowerShell 删除命令，要求模型保留文件并使用新的已授权目录，而不是切换到其他删除 API。未跟踪文件一旦被真实破坏，Git、版本号、类型和测试都无法恢复；原有工具名拒绝清单也不会检查已允许 Shell 工具里的命令。该检查只覆盖直接命令语法，不覆盖任意脚本副作用或编码命令，也不能替代操作系统隔离或宣称形成完整防删沙箱。模板指令改为调用现有选择器和填写器，不再手工重建 XML。失败运行被保留并停止，没有声称文件已恢复。

桌面技能投影把宿主已核验包视为执行边界，不要求模型运行只适用于独立安装包、但该包中不存在清单的自检。暂存阶段在签名前复用宿主操作清单解析器，使版本不一致在组装应用前被发现，而不是启动后才报错。

桌面下载和安装是两个独立的显式操作。完成下载的包在同一版本检查间保持就绪。macOS 控制器安装前再次核验暂存应用，并保留已签名归档以便续传。通知展示真实宿主状态和签名发行说明，不自动下载或退出。

个性化设置和对话工具通过同一个串行写入器共享隔离 DSH home 中的 `AGENTS.md`。只有文件不存在时写入默认值，明确留空或已自定义文件会被保留。指令重载由上游 `agent-instructions` 负责；编辑器长度限制不会成为模型步骤前置。待用户处理状态来自现有交互投影，自动任务插件声明其 `uiConversation` 依赖。

Electron 搜索会把 ripgrep 解析到 ASAR 解包后的物理路径，glob 与 grep 共用该解析器。Electron 文件系统能读取的虚拟路径不能直接交给操作系统子进程。普通 Node 和单文件 SDK 的旁车解析保持不变。中文 Chat 推理展示会同时检查可见预览与完整文字，因此英文段落中的中文文件名不会误露英文摘要。

## 备选方案

**客户端内文档预览。** 已确认的交互是用系统应用打开；增加预览引擎会改变该选择，并重复成熟文档应用的能力。

**写死应用列表。** 不同机器的已安装应用和默认项不同，原生枚举与系统选择器可以避免展示不存在的处理程序。

**新增注释数据库或偏好文件。** 现有展示元数据和 `AGENTS.md` 已提供持久身份，复制状态会在没有现实消费者的情况下增加同步故障。

**下载完成后自动安装。** 下载完成不代表用户同意中断工作，显式重启升级可在保留完整性核验的同时维持该区别。

## 后果

渲染器仍只负责展示。文件操作需要本地桌面支持，独立浏览器保留原有打开动作；Windows 使用原生选择器而不是虚构应用列表。现有发行签名、账户授权与回滚仍独立于文档质量检查。

单元与组件测试覆盖原生路径限制、已有文件保留、注释回放与选择、显式更新状态以及偏好读回。真实打包客户端、系统应用和升级证据写入产品发布记录；源码测试不能代替这些观察。
