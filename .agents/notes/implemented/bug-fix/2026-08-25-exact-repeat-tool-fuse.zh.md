# Agent Note：精确同参工具熔断

Status: implemented

[English](2026-08-25-exact-repeat-tool-fuse.md) | 中文

## 问题

建议型重复调用提醒无法阻止 agent 无限重复不可用或没有变化的工具调用。每次同参尝试都会继续消耗模型轮次，还可能重复外部副作用，或让桌面任务一直显示运行却不增加证据。Git 历史、语义版本、TypeScript 和普通测试无法阻止这种运行时模型行为，现有提醒文本也不能否决工具分发。

OpenCode 对同一工具输入采用三次 doom loop 阈值，OpenAI Agents 和 LangGraph 则提供更宽泛的轮次或图步骤上限。产品先需要更窄的控制：阻止已经确定无进展的精确操作，同时不对正常推进的长任务施加通用轮次预算。

## 决定

`@deepseek-ai/dsh-repeat-tool-reminder` 接受可选的 `blockAt`，其值必须是大于等于 2 的整数。插件按当前 live agent 比较工具名和完整规范化 JSON 参数；如果本次尝试将使连续计数达到 `blockAt`，`tools/pre-execute` 先保留下游的询问或拒绝决定，只在下游允许时于工具实现运行前返回拒绝。

`tools/post-execute` 仍是唯一的计数更新位置，因此已执行和被拒绝的尝试进入同一条链，配置阈值产生的提醒也继续能从会话日志重建。更换受跟踪工具、更改规范参数或收到用户新消息就是显式恢复路径。被排除调用继续对链透明，没有 agent 的直接执行不跟踪，各 agent 之间不共享链。

共创企业助手桌面组合在第 2、3、5 次配置提醒，并设置 `blockAt: 3`。第二次同参尝试仍执行并收到提醒；第三次及之后的同参尝试在分发前拒绝，直到 agent 改变动作或用户开始新一轮。拒绝结果直接返回模型，不打开可能在无头或隐藏窗口状态下无限等待的交互审批。

## 考虑过的替代方案

**通用轮次预算。** 暂缓，因为它会同时中止仍在推进的长任务，也不能指出造成失败的是哪一次重复操作。只有真实任务出现不断更换工具或参数的循环时，才为完整运行另行评估上限。

**模糊比较。** 否决，因为空白、路径、轮询参数和生成载荷的差异可能代表真实进展。精确规范相等具备确定性和可解释性；只有观察到明确漏检后才扩展。

**第三次调用弹出审批。** 否决，因为 agent 可能在窗口隐藏或没有审批界面的环境运行。等待弹窗会把一种不终止状态替换成另一种。

**删除建议层。** 否决，因为第二次提醒允许模型在不阻止合理重试的前提下自行恢复，第三次拒绝再提供硬上限。

## 结果

同一用户轮次中，产品不会把完全相同的受跟踪工具和规范参数连续执行超过两次。熔断不声称识别更换参数后的语义循环，也不替代专业纠正上限和深度澄清无进展规则。没有配置 `blockAt` 的部署继续保持仅提醒行为。

## 验证

包测试通过真实 agent loop 连续尝试四次相同调用，断言只有前两次进入工具实现、后续工具结果为错误、下游策略优先级不变、改变调用后恢复、用户新轮次重置状态且非法 `blockAt` 在加载时失败。产品组合测试固定 `blockAt: 3`。无密钥组装应用快照重放重复调用，记录提醒与执行前拒绝。
