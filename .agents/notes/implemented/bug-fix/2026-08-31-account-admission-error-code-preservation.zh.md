# Agent Note: 账号准入错误码保持不变

Status: implemented

[English](2026-08-31-account-admission-error-code-preservation.md) | 中文

## Problem

账号准入已经把传输失败、未登录、必须升级和设备冲突归类为稳定的 `GC-ACCOUNT-*` 诊断，但 `requireCurrentDevice()` 在归类后抛出了普通 `Error`。智能体循环只保留有类型的 `LlmError`，其他错误会被映射为 `UNKNOWN`，因此同一轮同时显示有用的账号诊断和无关的终止码。

## Decision

所有可能终止模型请求的账号准入拒绝都以 `LlmError` 穿过智能体循环。网络失败保持 `GC-ACCOUNT-NETWORK`；未登录、必须升级和设备冲突保留各自账号错误码及产品安全文案。原始失败继续作为 cause 留给 Host 诊断。

渲染器在首次加载、窗口重新可见以及窗口可见期间每六十秒执行后台账号刷新。每次模型请求仍独立核验当前设备，因此降低展示轮询频率不会削弱单设备准入。

## Alternatives considered

**让智能体循环解析账号错误文字。** 已拒绝，因为产品专属的字符串匹配会重复结构化错误分类，并在文案变化后失效。

**只在渲染器中隐藏终止 `UNKNOWN`。** 已拒绝，因为会话日志和非渲染器消费者仍会收到错误的失败身份。

**取消逐请求核验，只依赖轮询。** 已拒绝，因为渲染器轮询只负责刷新展示，不是请求时强制当前设备的安全检查。

## Consequences

一次账号失败只会在轮次结果和日志中产生一个稳定错误码，同时保留完整诊断原因链。后台流量减少，请求时账号安全保持不变。
