# Agent Note: 路由 Flash 任务的有界收敛

Status: implemented

[English](2026-08-31-bounded-flash-task-convergence.md) | 中文

## 问题

DeepSeek Harness 可以并发派发同一助手步骤中互不影响且声明为并发安全的工具调用，但不能强制模型把独立读取合并到一个步骤。产品真实会话中的长文档任务会产生大量串行模型步骤，并重复输入和环境均未变化的失败方案，因此 Host 已有的并发能力没有缩短墙钟耗时。

## 决策

产品自有的 DeepSeek V4 Flash 与 Pro 路由引导要求模型把互不依赖的读取、检索和解析合并到同一工具调用，同时保持写入、外部动作和有前后依赖工作的顺序。失败路径在状态未变化时只允许一种有新依据的替代方案；第二次仍无进展时结束该路径、保留原始输入，并说明继续所需的最小条件。

这些指令补充 Harness 调度器，不改变 AgentLoop 顺序或工具安全声明。它们不改变用户选择的推理强度，不增加墙钟总时限，也不会把不支持的输入伪装成成功结果。

## 验证

路由组合测试断言持久系统段包含两项规则，且复杂任务的近场引导要求批量执行独立读取。同一套测试使用每条允许的 DeepSeek V4 Flash 与 Pro 路由启动真实 SystemPrompt 组合，并确认既有 persona、技能、上下文和工具均未被移除。

## 考虑过的替代方案

**让所有工具并发。** 不采用，因为写入、Shell 命令、外部动作和相互依赖的读取不能只为降低耗时就重叠执行。

**降低 OpenCode Go 推理强度。** 不采用，因为这会隐式改变产品策略。推理强度仍是用户可见的质量与耗时选择，不能作为隐藏的性能补丁。

**增加轮次总时限。** 不采用，因为时限也会终止正常的长文档工作，而且不能阻止到达时限前反复执行许多短模型步骤。

## 后果

路由模型会收到直接指令，使用 Host 已提供的并发能力并停止状态未变化的失败循环。当模型生成本身缓慢、排他工具确实耗时或外部服务不返回时，任务仍可能较慢；这些情况继续作为可观察失败处理，而不会被写成已完成。
