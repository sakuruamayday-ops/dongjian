# Agent Note: 地区启动陈旧写入保护

Status: implemented

[English](2026-09-02-region-startup-stale-write.md) | 中文

## Problem

渲染器会在 Host 返回已持久化的连接器地区前先投影“全部”。Host 恢复已确认城市后，选择器草稿仍可能保留该占位值。来自占位状态的延迟操作随后可能在应用更新启动期间把“全部”写回，使用户状态保留结果取决于进程时序。

## Decision

选择器关闭时，草稿跟随最新 Host 地区；用户明确打开选择器后，草稿保留正在编辑的选择。每次地区修改都会携带操作形成时最后可见 Host 快照中的地区与确认状态。目标值已经实现时，Host 将操作视为幂等；否则，预期旧值与当前持久化状态不同时拒绝修改。

比较发生在真正持久化选择的 Host 操作中。渲染器同步减少陈旧操作，Host 比较则阻止延迟调用或其他调用方提交陈旧值。

## Alternatives considered

**把第二次更新验收通过视为充分证据。** 未采用，因为此前的精确安装包失败已经证明时序覆盖真实可达；一次有利调度不能消除缺陷。

**只同步渲染器草稿。** 未采用，因为异步渲染器无法让持久写入与它观察到的 Host 状态保持原子一致。

**让所有连接器读取和界面活动等待启动完成。** 未采用，因为普通启动与连接器发现不需要全局等待。针对地区状态的预期值比较可以处理冲突修改，同时不阻塞无关工作。

## Consequences

当其他已提交值取代操作所依据的快照后，地区修改会明确失败，用户可重新打开选择器并基于当前状态重试。首次选择和普通修改在基线仍为当前值时继续即时生效。组件与 Host 测试分别固定请求元数据和陈旧写入拒绝行为；安装包更新验收覆盖更新、重启与回滚期间的持久地区。

安装包验收只观察恢复状态，不写入地区或工作区设置。工作区根目录 IPC 返回前页面已经可以渲染，因此验收会先读取根目录及其确认状态，再等待加载弹窗消失。延迟组件夹具把这一加载区间与真正未配置根目录区分开；若持续要求重新设置，验收仍判失败。
