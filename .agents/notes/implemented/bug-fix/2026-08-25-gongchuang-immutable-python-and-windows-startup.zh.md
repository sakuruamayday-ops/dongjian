# Agent Note: 共创不可变 Python 与 Windows 启动

Status: implemented

[English](2026-08-25-gongchuang-immutable-python-and-windows-startup.md) | 中文

## Problem

桌面端曾把 formal 签名内嵌 Python 目录放到进程级 `PATH` 最前方。获准执行的 PowerShell 任务因此可能解析到包内 `pip`，并把新依赖写入应用资源。精确签名文件校验器在下次启动时会正确拒绝新增文件，但损坏客户端在更新配置之前就按设计失败关闭，无法进入更新流程。反馈中的 Windows 安装还会为每次凭据读取创建一个 PowerShell 进程并重新编译 Credential Manager 适配器；应用归档同时保留源码映射和开发生成目录，增加了解包与杀毒扫描工作量。

完整性失败不能通过弱化验签解决。运行时必须不再作为通用命令行环境暴露，启动失败还需要一条不依赖损坏运行时、并能取得已验证完整安装包的恢复路径。

## Decision

桌面端不再导出内嵌 Python 可执行文件，也不再把其目录加入 `PATH`。产品自有的文档和 OCR 操作继续通过类型化运行时绑定取得签名解释器绝对路径。子进程环境禁止用户 site-packages 和字节码写入，并要求单独调用的 `pip` 必须处于虚拟环境。formal 运行时暂存会在计算精确签名索引前移除 `pip`、其分发元数据和启动器以及 `ensurepip`，同时保留 Python 标准库、文档依赖、PaddleOCR 依赖和已发布消费者所需的 setuptools 模块。

打包应用启动失败继续失败关闭。错误对话框新增完整修复安装包入口，使用当前正式版 macOS arm64、macOS x64 或 Windows x64 的稳定门户路由。服务器只选择当前已发布记录，验证登记路径、体积、SHA-256 和签名状态后，以禁止缓存方式传输完整 DMG 或 EXE。旧应用不安装未验证归档，也不绕过启动完整性；用户仍通过操作系统正常安装流程运行已验证完整安装包。

Windows Credential Manager 在每个提供器生命周期中只使用一个延迟启动的隐藏 PowerShell 会话。该会话只加载一次原生适配器，通过标准输入接收串行化的逐行 JSON 操作，从不把秘密放入进程参数；每次请求都有时间上限，响应损坏或进程失败后会重启。提供器销毁时会等待已排队凭据操作完成，再关闭会话。

桌面应用归档排除源码映射、TypeScript 编译状态、覆盖率目录和嵌套生成输出，打包校验器会拒绝这些路径重新出现。原生可编辑右键菜单即使在 Chromium 剪贴板能力探针错误报告 Windows 剪贴板为空时也保持“粘贴”可用；实际操作仍由 Chromium 执行，空剪贴板仍然不产生内容。

## Verification

运行时暂存测试证明签名索引不含 `pip`、`ensurepip`、相应元数据和启动器，同时保留必需 Python 模块。启动测试证明打包应用完整性失败只提供稳定平台修复路由，不弱化原失败。门户测试接受三种受支持产物，并拒绝不支持的架构或签名状态不可发布的产物。凭据测试覆盖单会话、串行且秘密安全的请求、失败重启、超时和生命周期关闭。归档与右键测试分别拒绝开发载荷，并在剪贴板探针为 false 时保留粘贴。

正式发布验收仍检查完整运行时和技能文件集合、每个 SHA-256 摘要、Ed25519 身份、原生架构、归档内容和 macOS 应用签名。macOS arm64 在当前设备运行，macOS x64 在 Rosetta 下运行；Windows 延续既有未签名发布例外，执行跨构建静态验收并在发布后收集主人反馈。

## Alternatives considered

**缓存上次验签结果或容忍额外运行时文件。** 未采用，因为两者都会弱化既有精确完整性保证，使包体变更无法与损坏或隔离区变化区分。

**保留包内 `pip`，只从界面隐藏。** 未采用，因为任何继承进程环境的获准 Shell 仍可能解析并改写签名运行时。

**原地修复个别运行时文件。** 未采用，因为局部修复需要第二套受信任依赖解析器，还可能形成混合版本应用；完整安装包已经提供唯一签名且精确的应用镜像。

**每次凭据请求都重新启动 PowerShell。** 未采用，因为所有请求本来就在同一桌面用户和 Credential Manager 权限下执行，重复创建进程与 `Add-Type` 编译没有增加隔离价值。

**剪贴板探针为 false 时禁用粘贴。** 未采用，因为该探针在已报告的 Windows 配置中不是权威状态。让 Chromium 执行粘贴既保留原生语义，也不需要应用代码读取剪贴板内容。

## Consequences

模型任务不能再通过普通 `python` 或 `pip` 解析改写签名内嵌运行时，formal 运行时也减少了小文件。V0.2.7 之前已损坏的安装仍需要手工执行一次完整覆盖安装，因为旧二进制不含新修复动作；V0.2.7 及后续版本可在启动失败关闭后打开稳定的已验证安装包路由。Windows 启动避免重复 PowerShell 初始化，归档不再携带开发专用字节；但真实 Windows 设备冷启动耗时仍是发布后测量事实，不是源码承诺。本决定扩展而不替代[共创桌面启动清理与 UTF-8 诊断](2026-08-23-gongchuang-desktop-startup-cleanup-and-utf8-diagnostics.zh.md)中的精确启动对账。
