# Agent Note: 共创产品完整启动证明

Status: implemented

[English](2026-08-29-gongchuang-complete-product-boot-proof.md) | 中文

## 问题

Electron 壳可以完成 CSP 引导并创建就绪窗口，但产品插件仍可能在激活时失败。仅观察引导清单、实时模块加载器、CSP 控制台与窗口标题的生命周期检查，会把错误页误判为可用产品。产品插件还会读取嵌套的 `remote.llm` 服务；Cordis 对该属性和父级 `remote` 服务分别授权，缺少精确注入声明会使产品壳无法挂载。

## 决策

共创产品插件同时声明 `remote` 与 `remote.llm`。真实组合回归通过 Loader 和测试专用 `cordis.yml` 加载 Typert、API Gateway、Remote contributions 与产品插件；删除嵌套注入会使 Loader 激活失败，生产声明则会渲染可见产品壳。

打包后的 macOS 验收和尚未提交的客户端内更新都会等待产品 body 标记和尺寸非零、实际可见的 `ProductSidebar` 根节点，要求引导页消失，并拒绝可见的插件失败。更新事务只有在这些条件成立后才能提交。生命周期脚本在关闭后再次检查完整启动日志。渲染器错误、插件失败页、产品根节点缺失或不可见、CSP 拒绝，以及受控启动失败场景中意外出现的就绪窗口，都会使本次运行无效。

## 验证

Loader 组合测试的负例只替换产品命名空间，并观察精确的嵌套服务授权失败；正例观察 body 标记、侧栏贡献与可见产品名称。真实侧栏元素携带打包验收读取的稳定产品根标记。桌面测试固定完整渲染器回执，并以有效、无效及晚到日志执行生命周期辅助函数。

## 曾考虑的替代方案

**把 BrowserWindow 就绪视为产品就绪。** Electron 窗口就绪只能证明文档已经加载，不能证明所有 Loader 条目均已激活，也不能证明产品 UI 已替换引导页。

**只声明父级 `remote` 服务。** Cordis 对嵌套属性执行精确授权，父级声明不能授权 `ctx.remote.llm`。

**只检查首次观察到的日志前缀。** 渲染器与 CSP 错误可能晚于第一条成功日志。重新检查完整启动日志，可以让验收结论覆盖完整进程生命周期。

## 后果

产品 UI 始终无法完成时，打包验收最多增加十五秒等待，随后以实际探针状态失败，不会接受引导文档。产品的精确 Remote 依赖同时体现在注入声明和可执行组合测试中。生命周期回执专属于共创产品标记，不能作为其他桌面组合的通用就绪信号。
