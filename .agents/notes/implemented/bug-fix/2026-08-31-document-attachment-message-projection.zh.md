# Agent Note: 文档附件消息投影

Status: implemented

[English](2026-08-31-document-attachment-message-projection.md) | 中文

## 问题

文档导入为模型保留了受控文件引用，但只要输入框同时有文字，产品提示词聚合器就会覆盖面向用户的附件投影。附件仍属于请求，发送和重载后的对话却只显示用户指令。

## 决策

文档准备结果提供仅用于展示的前置内容，按顺序保存受控导入引用。产品聚合器把它与用户原始输入组合，同时保持模型提示词组合不变。待提交回显、排队插话和持久用户消息消费同一份展示文本。

产品提供方只识别开头连续出现、并且精确符合 `@"共创导入资料/<文件名>"` 的产品导入行；通用 Chat 渲染器只消费结构化投影，不感知产品路径约定。每个合法引用在用户正文上方渲染为紧凑文件按钮，只显示文件名，点击动作交回同一个产品提供方。提供方认领整个受控导入命名空间，因此畸形路径不会回落到通用 workspace opener；Electron Host 会重新解析当前企业空间，并在 `openImportedDocument` 中执行路径包含、常规文件与符号链接校验。行内引用、其他目录、嵌套路径、遍历片段、控制字符和非法文件名保持普通文字，绝不会变成文件打开控件。只有文件的消息不生成空白文字气泡，复制操作只接收用户原始正文。

## 曾考虑的替代方案

**显示完整的模型提示词。**不采用，因为这会在用户消息中暴露产品生成的上下文和深度澄清包装文本。

**从已发送文本中的任意引用猜测附件。**不采用，因为普通用户引用不能证明路径来自受控导入器，不应获得文件打开动作。

**增加新的持久附件数据结构。**暂不采用，因为现有持久 `displayText` 已经贯通本地回显、队列、插话和重载，不需要改变线协议。只有未来消费方需要超出本次受控展示的稳定附件身份时，结构化字段才有必要。

## 后果

新的文字加文档消息会在指令上方持续显示每个导入文件，在持久接纳前后保持一致，多文件顺序与导入顺序相同。点击沿用现有文件打开错误处理，复制不包含文件引用，畸形引用保持不可交互。旧客户端创建且持久展示文本中没有附件引用的历史消息无法由本投影还原，继续保留原有外观。
