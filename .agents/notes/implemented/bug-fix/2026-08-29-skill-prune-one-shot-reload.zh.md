# Agent Note: 技能指令剪枝后的单次恢复

Status: implemented

[English](2026-08-29-skill-prune-one-shot-reload.md) | 中文

## 问题

工具结果修剪器曾把较长的 `skill` 加载结果当作普通命令输出处理。通用中部标记虽然说明部分文本缺失，却没有表明缺失内容属于指令，也没有告诉模型如何恢复，因此正式技能可能只加载了残缺内容，却没有可执行的继续路径。

## 决策

修剪器根据结果配对的持久 `tool/call` 识别技能结果，不根据输出文本猜测。最新一条直接用户消息之后，某个具名技能第一次被修剪时会携带可识别的 `reload="available"` 标记，并给出通过现有 `skill` 工具重载完整指令所需的精确调用。同一技能在下一条直接用户消息之前再次被修剪时会携带 `reload="used"`，并要求模型不得仅因该标记继续重载。同一份剪枝快照中已经存在多份相同技能的长结果时，只有最新一份提供恢复机会。

恢复路径复用现有 `skill` 工具及其精确 `name` 参数，不增加分页协议、第二套指令存储、自动调用或兼容层。普通工具即使输出类似 `<skill_content>` 的文本，也继续使用通用标记。

## 已考虑的替代方案

**让每个剪枝标记都推荐 `skill` 工具。** 未采用，因为普通工具不能通过 `skill` 恢复，文本相似也不是持久的工具身份。

**自动重载，直到完整正文不再被修剪。** 未采用，因为较长正文可能反复跨过同一阈值，造成无界工具循环。

**为 `skill` 增加偏移与分页参数。** 未采用，因为当前没有调用方消费分页技能指令；现有完整加载操作足以提供一次显式恢复机会。

## 后果

模型可以把残缺技能指令与普通截断输出区分开，并在每段直接用户继续过程中得到一次有界恢复机会。第二个标记会放弃该继续过程中的进一步自动恢复，并以保留的头部与尾部作为可用指令。若自定义阈值连恢复提示本身也无法容纳，则回退到已经过校验的通用标记，而不是超过配置上限。单元测试固定了精确重载路径、单次停止以及普通工具行为不变；无密钥 `skill-prune-recovery` 录制会话证明正式 `skill` 与压缩路径会发出可见恢复标记。
