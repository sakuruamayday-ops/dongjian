# Agent Note: 文件进草稿且不自动发送

Status: implemented

[English](2026-08-24-document-intake-without-auto-submit.md) | 中文

## 问题

桌面拖放原本只接受图片，选择文件后还会在用户补完指令前开始任务，原生选择器每次也回到默认位置。这与对话草稿的语义不一致。

## 决策

桌面 Host 接受来自选择器或拖放的常规文件，拒绝目录和符号链接，并把合格副本写入当前企业空间。导入成功后把企业空间相对路径保存在产品持有的会话级附件状态中，绝不调用发送，也不修改可编辑输入框。可见文件卡就是完整的成功状态，不再增加重复提示条或草稿说明。存在待发送文件时，即使输入框没有文字也允许发送。只有用户真正提交任务时，提示词准备层才向模型文本附加受控引用。当前持久展示由[文档附件消息投影](../bug-fix/2026-08-31-document-attachment-message-projection.zh.md)负责：每个导入文档在发送和重载后都持续显示在用户原始输入上方。排队项、插话、重载历史、复制操作和聊天气泡都不会暴露产品生成的模型上下文。发送失败保留附件，发送成功后消费附件。旧客户端生成的草稿附件块会迁入同一状态，已经发送的旧式附件尾注也只在展示层移除。纯受支持图片拖放保留图像附件路径；混合或非图片拖放使用文档导入。

选择器记住上次成功选择的父目录。导入上限为 20 个文件和单文件 128 MiB，过长文件名缩短后保留扩展名。沙箱渲染器只能通过 preload 中 Electron `webUtils.getPathForFile` 取得本机路径。

## 曾考虑的替代方案

**导入成功后立即发送。**不采用，因为文件选择只是用户消息的一部分，不能提交尚未完成的任务。

**把所有文件当作图片附件。**不采用，因为任意文档需要稳定的工作区路径，也不应继承图像模型要求。

**递归扫描目录。**不采用，因为这会扩大范围和数据暴露，当前也没有目录导入需求。

## 后果

用户可以先加入文件，再在没有自动说明文字的输入框中完成指令，也可以只发送附件。发送或重载后，持久聊天投影会把简洁文件标签保留在用户原始指令上方。模型读取的文件引用仍完整落盘，导入路径在企业空间内可审计，选择器会回到上次位置。移除文件卡只改变待发送轮次的引用。打包客户端验收仍需验证真实拖放、选择器目录恢复、附件单独发送、模型文本与展示文本分离、旧草稿与历史展示迁移，以及没有自动发送。
