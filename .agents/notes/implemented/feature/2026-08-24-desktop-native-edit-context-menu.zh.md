# Agent Note: 桌面原生编辑右键菜单

Status: implemented

[English](2026-08-24-desktop-native-edit-context-menu.md) | 中文

## 问题

桌面渲染器没有在输入框右键时提供编辑命令，用户选中生成正文后也缺少可靠的右键复制动作。若由渲染器仿制菜单，需要重复实现平台剪贴板可用状态，还可能与最近对话等侧栏行已有的产品菜单冲突。

## 决策

Electron 主进程监听桌面窗口的 Chromium `context-menu` 事件。可编辑目标使用原生 `cut`、`copy`、`paste` 和 `selectAll` role，并按 Chromium 的编辑标志启用；非编辑目标只有在 Chromium 报告存在选中文本时才显示原生 `copy`；其他页面空白不显示主进程菜单，因此渲染器已有的产品菜单保持原行为。

Electron 原生 role 始终作用于当前聚焦控件或正文选区。粘贴与剪切会经过浏览器正常输入事件更新受控草稿，复制直接读取当前选区，不在产品状态中复制正文。

## 曾考虑的替代方案

**在渲染器中自制编辑菜单。**不采用，因为这会重复平台剪贴板规则、键盘行为、焦点与可用状态，Electron 已提供这些能力。

**任何位置右键都打开编辑菜单。**不采用，因为页面空白没有编辑动作，全局菜单还会干扰侧栏条目已有的右键菜单。

## 后果

桌面文本编辑遵循操作系统菜单行为，生成正文无需新增工具栏即可复制。该能力只属于桌面端，浏览器部署继续使用浏览器原生右键菜单。单元测试固定可编辑目标、正文选区、禁用命令和空目标模板，打包桌面验收负责验证剪贴板往返。
