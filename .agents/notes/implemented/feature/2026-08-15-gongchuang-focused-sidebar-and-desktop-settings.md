# Agent Note: Gongchuang focused sidebar and desktop settings

Status: implemented

English | [中文](2026-08-15-gongchuang-focused-sidebar-and-desktop-settings.zh.md)

## Problem

共创企业助手 fixes one professional Agent composition and invokes search as part of policy, peer, checkup, and report workflows. A second new-task button, a standalone search page, two permanent policy-status badges, and a selector containing one Agent preset consumed the sidebar space needed for recent enterprise conversations without offering distinct user actions. The inherited DSH settings trigger was also visually inconsistent with the product shell and did not provide the native update or profile actions desktop users expected.

## Decision

The product sidebar owns one `新对话` action. Selecting it enters the assistant and starts a new workspace session. Enterprise space, Skills, MCP, and Automation remain primary destinations; search has no route or page. Professional skills and the signed Host continue to invoke `web_search`, `web_fetch`, and the 共创 search connector when a business task requires evidence retrieval.

The signed Host requires the `gongchuang` Agent preset as the only system-trusted composition and disables `ui-agent-preset`. The preset still decides the prompt, tools, skills, and validation plugins for every session, but users cannot select, copy, edit, or bypass it. Policy and skill validation also remain mandatory without a steady-state badge: invalid signatures fail application launch, and a task that lacks a required professional or delivery receipt fails at that task with an actionable error.

The account footer exposes product-owned Profile and Settings actions without repeating client or skill versions in the main sidebar. Profile accepts JPEG, PNG, or WebP files up to 5 MB, decodes and center-crops them to a 256-pixel WebP image, and persists only that local data URL. The saved image and account name render only while the server session is `connected`; expired, superseded, authenticating, and disconnected states use a generic signed-out icon. Signing out requires an explicit confirmation that server synchronization, skill synchronization, and MCP directory synchronization stop while enterprise directories, conversations, and generated files stay on the device.

Settings uses compact product-owned rows and exposes only operations backed by a live service. The General page no longer repeats installation-time model choices, a single professional preset, or desktop runtime toggles. Title-bar close is a fixed product behavior rather than a preference: it hides the main window and retains the desktop runtime until the user selects `退出应用` from the tray menu; tray activation restores and focuses the window. This behavior does not block system sleep, and the client does not configure Electron `powerSaveBlocker`. Client and skill-bundle updates remain independent panels. The desktop package, Host window, signed product policy, and portable runtime share the client semantic version while the bundled skill-suite version advances independently. The product policy continues to pin the client and bundled skill baseline, while professional contracts and signed operations bind to the exact active suite version selected by the Host after its Ed25519 and file-inventory checks. An independent suite update therefore cannot fail only because it is newer than the bundled baseline, but an unsigned suite, a mismatched operation registry, or changed file still fails closed before the main window opens. The updater reports `app.getVersion()`, and an unavailable renderer bridge displays an unknown/read-pending state instead of a hard-coded version. Desktop packaging emits platform artifacts before deterministic metadata: macOS publishes the [self-managed Ed25519 manifest and detached signature](2026-08-20-gongchuang-self-managed-macos-updates.md), while Windows retains `latest.yml`; missing metadata is an update error, not proof that the installed client is current.

The sidebar brand gives the complete `共创企业助手` name priority over secondary controls: the region selector occupies a compact second line instead of truncating the product name. A Recent Conversations section with no enterprise space renders the explicit value `无`, and an enterprise space with no recent conversations renders `无` instead of the number zero. The active conversation uses one WorkBuddy-style shallow grey rounded fill across the complete row; each conversation is a single row with its title on the left and borderless timestamp on the right. Keyboard focus remains visible as a one-pixel low-contrast outline. Conversation actions stay hidden by default; hover or keyboard focus replaces the timestamp with shared, tooltip-backed More, Archive, and Pin icons. The composer model control is a frameless text-and-chevron trigger; hover and keyboard focus use a low-contrast surface instead of drawing a box around the selected model.

Recent enterprise spaces and their conversations preserve Host order and support pointer-driven reordering through the existing insert-before operations. Rows keep the ordinary arrow cursor and do not expose a drag handle, grab cursor, or browser drag ghost. Holding the primary pointer button for 180 milliseconds captures that pointer and starts direct movement, while a short click keeps its normal open or expand action. A compact product-owned preview follows the pointer with the enterprise-space or conversation title, the source row becomes a subdued placeholder, and a two-pixel insertion line or inset destination-space outline identifies the pending drop. The preview is visual-only, ignores pointer events, and clamps to the viewport so narrow windows retain the complete drag path without horizontal overflow. Pointer moves that resolve to the same target reuse the existing state instead of rerendering the list. A conversation released over another enterprise space uses the existing move operation. Searching disables reordering, and a running conversation cannot start a drag. The renderer never speculatively mutates list order, and a rejected operation surfaces a redacted product error while leaving the Host projection unchanged. Pin and unpin use the persistent workspace service; pinned conversations project first while both the pinned and ordinary groups retain `sessionIds` order.

Recent enterprise conversations expose a keyboard-accessible context menu for open, copy, rename, archive, and delete. Both `复制` and `移动到企业空间` open their submenus immediately on pointer hover, while Right Arrow remains the keyboard entry and moving to another primary action closes the open submenu. Moving is represented once as `移动到企业空间`; when filtering leaves no target, its submenu displays the accessible, non-interactive empty value `无`. The earlier duplicate `项目` row and separate move dialog are removed. Enterprise-space rows expose the same pointer and keyboard context-menu route for editing the enterprise name, archiving, and removal. Enterprise detail provides the same archive/delete distinction for conversations and workspaces. Archive and delete only change the client registry: neither operation removes enterprise directories, generated files, or session logs. Settings lists only archived workspaces and archived conversations. Each archived row can be restored or deleted directly; deleted rows disappear from every product list and have no product restore action.

The new-conversation Workspace picker keeps search and existing-space selection, but the Gongchuang composition replaces the generic directory-add row with `新建企业`. That row closes only the picker and opens the same one-shot named-enterprise dialog over the current new conversation; it does not navigate to the Enterprise Space page, create another picker state, or silently adopt an arbitrary directory. Successful creation attaches and opens the new enterprise's Session through the existing Workspace operation. `不在企业空间工作` remains available as the explicit unscoped route.

The first-use dialog combines the required city choice with the enterprise workspace root. The desktop Host prepares `Documents/共创企业空间`, requires explicit acceptance before entry, and allows an existing directory to replace it through the system picker. New-enterprise creation accepts one portable directory name and creates an immediate child under the active root; importing connects a concrete existing directory in place. Settings changes the root for later creation without moving existing workspaces. The sandboxed preload exposes only these typed operations, and the main process rejects requests from any renderer other than the active product window.

The conversation composer exposes a native `文件` action. The main process accepts only DOCX, XLSX, PPTX, PDF, and TXT files explicitly selected through the system dialog, copies regular files into `共创导入资料` under the current concrete enterprise workspace, and returns a redacted relative-path receipt to the renderer. Source paths, arbitrary directory scans, and source bytes do not enter the renderer. An operation from the active signed skill suite then extracts document text; text and scanned PDFs have distinct states, and a scanned document cannot become factual input until configured OCR succeeds.

## Alternatives considered

**Keep both new-task controls with different copy.** Rejected because both created the same workspace session and made users choose between identical actions.

**Keep a standalone search page as an advanced tool.** Rejected because evidence retrieval belongs inside professional workflows; a separate page encouraged context-free searches and duplicated the MCP and skill orchestration already available to the model.

**Keep permanent green policy badges.** Rejected because the signed policy has no supported off state. A green badge consumed space without enabling an action, while a real validation failure must block work where it occurs.

**Expose the one-entry Agent preset selector.** Rejected because it implied a choice and exposed developer authoring controls. Removing the Host preset itself was also rejected because it would remove the fixed professional composition the product relies on.

**Open a download website from Settings.** Rejected because it cannot distinguish current, available, downloaded, and install-ready states. The authenticated in-client updater owns those transitions after the one-time macOS bridge installation, while the server feed remains deployment configuration.

**Expose window-closing or sleep-prevention switches.** Rejected because closing to the tray is the product default, not a user preference, while preventing system sleep is unrelated to keeping the client runtime available and wastes battery when enabled accidentally. The tray retains the explicit exit path.

**Reuse the general workspace directory browser for every new enterprise.** Rejected because ordinary creation needs only an enterprise name and must produce a direct child of one visible root. The broader browser remains a browser-mode fallback, while desktop import uses the system directory picker for an existing concrete directory.

## Consequences

The sidebar shows more enterprise conversations at the same window height and every visible primary item performs a distinct product action. Its complete product name remains readable, empty enterprise-space states are unambiguous, and the active-conversation treatment no longer dominates the content. A new conversation can begin in an existing enterprise space, create one, or remain ungrouped without changing existing enterprise registrations. Search, policy enforcement, and Agent composition are less visible but remain mandatory runtime behavior; diagnostics appear only when the user can act on a failure.

Avatars are device-local and do not synchronize through the account server. A saved avatar remains available for the next valid login but never represents an invalid server session. Automatic update availability depends on the configured platform feed and its complete referenced artifacts. On macOS the installed Host authenticates the exact server JSON and detached signature before selecting an architecture archive; on Windows the Electron metadata channel remains separate. Client releases do not rename or advance the installed skill-suite version. The product shell does not expose the generic DSH Settings or Agent authoring pages.

Closing the title-bar control does not quit the client. Users restore it by selecting the tray icon and intentionally stop it with the tray `退出应用` command. This preserves in-flight local runtime work without requesting a system-wide sleep blocker; an operating-system restart or explicit quit still terminates the process.

Imported copies remain in the current enterprise workspace and can be reused by later conversations for that enterprise, reducing repeated upload and extraction. Model-cache reuse still depends on a stable conversation prefix and is not guaranteed merely because a file was imported. Legacy Office files, archives, and bulk document-directory scanning remain outside V0.1.

The enterprise root is device-local and independent of the installation directory. Changing it does not migrate or delete customer files; users who want a physical move perform that outside the client and reconnect the resulting concrete directory.
