# Agent Note: 共创会话轮次滑轨

Status: implemented

[English](2026-08-20-gongchuang-conversation-turn-rail.md) | 中文

## Problem

较长的企业工作对话会增加回看早期需求、纠正意见和决策的难度。另建导航页面或持久化大纲会复制 transcript，引入同步与恢复规则，并且在用户只需要定位当前对话时持续占用有限的侧边栏空间。

## Decision

共创企业助手通过现有 `conversation.session.header.utilities` slot 注册会话定位能力，并把透明细轨定位在当前 transcript 滚动区左缘。每条开启轮次的普通用户消息对应一条短横线。转向消息和注入上下文仍归入其所属轮次，不生成导航项。

细轨在 transcript 每次恢复或扩展后从 `ConversationSnapshot.chat.order` 和 `chat.nodes` 派生，不保存独立大纲或持久化导航记录。每项保留 Chat 节点键，该键已经渲染为 `data-chat-anchor-key`；用户选择后定位该行并调用对话滚动容器的原生滚动，因此现有滚动位置处理会自然观察此次移动。滚动与尺寸观察会更新当前短线并保持细轨对齐，不改变正文宽度。

每条短线都是可用键盘聚焦的按钮，带中文无障碍标签，并在原生 tooltip 中显示限定长度的消息预览。悬停或聚焦时短线变长，当前视口轮次使用产品活动色，ARIA 实时区域播报定位结果。至少两轮时才显示细轨，单轮对话不增加视觉元素。

该产品组件只依赖现有会话头部工具 slot、transcript 滚动区和 Chat 行标识，不新增侧边栏页面、Session 字段、持久化格式、服务或核心对话分发分支。

## Alternatives considered

**增加固定的宽幅右侧时间线。** 未采用，因为它会永久压缩对话阅读宽度并增加新的响应式窗格。透明细轨不挤占阅读列。

**使用折叠的页头菜单。** 未采用，因为它隐藏了轮次概览，而且每次定位都要多点一次。可见短线能持续提供位置感，并且不增加面板。

**持久化独立轮次索引。** 未采用，因为 Session transcript 已经决定轮次顺序与恢复结果；第二份记录可能在历史分页、分支或重放期间发生漂移。

**在通用对话包中增加产品专属滑轨。** 未采用，因为头部工具 slot 和稳定的 Chat 行标识已经提供所需的组合与定位接口。将滑轨保留在产品包中，可以保持上游对话包不受侵入。

**把转向消息和上下文行计为轮次。** 未采用，因为它们不会开启新的助手轮次，否则显示数量会偏离用户对“一次提交及其回答”的理解。

## Verification

组件测试固定轮次派生、转向消息与上下文排除、细轨持续呈现、中文无障碍标签、精确锚点滚动、窄窗口长文本预览，以及从恢复或前置补载历史中重建列表。产品包 TypeScript 程序验证现有 slot 和运行时快照类型。

## Consequences

用户无需离开 transcript 即可回看长对话，历史恢复也会自动重建相同的导航选项。滑轨只能定位 Chat 视图当前已渲染的消息行；当其他会话视图占用正文时，它会播报需要返回对话视图，而不创建跨视图导航状态。
