# Agent Note: 将选中的对话正文引用到输入框

Status: implemented

[English](2026-08-21-gongchuang-quote-selection-into-composer.md) | 中文

## Problem

用户阅读长回答时，常需针对其中一句或一段继续提问。复制、滚动到输入框、粘贴并手工标记原文会打断阅读；如果选中后自动发送，又会让用户失去补充真正问题的机会。

## Decision

用户在同一条已定稿的用户或助手正文内通过双击、指针拖选或键盘选择形成非空原生选区时，选区附近显示一个轻量菜单表面操作。`添加到对话`把所选各行作为 Markdown 引用追加到当前草稿，逐字保留既有草稿，在末尾留出继续提问的空行，把焦点和光标交回当前输入框，并且绝不自动发送。

该操作由 ChatView 持有，因为它能证明 Selection 两端属于同一个带键会话行，也能调用当前 Session 的输入动作。普通正文、可见链接和代码文字以及折叠行中的可见文字均可引用。工具行、真实按钮和自定义按钮控件、输入框、文本域、可编辑区域、跨行选区和空选区都不会触发。Escape、外部鼠标按下或滚动可以关闭操作。视觉表面复用标准菜单背景、反色细边、圆角、阴影、悬停和焦点令牌，不增加产品专属颜色。

## Alternatives considered

**在每条消息旁永久显示操作。** 不采用，因为用户仅阅读时也会给每一行增加长期视觉噪声。

**选中后立即发送。** 不采用，因为选文只是上下文，不是完整用户请求，立即发送会产生误操作轮次。

**把剪贴板作为中间存储。** 不采用，因为会覆盖无关剪贴板内容，且仍需用户完成粘贴和聚焦操作。

## Verification

ChatView 测试在助手正文、链接文字、代码文字和思考折叠行中创建原生 Selection，把精确引用追加到已有草稿后，验证 submit 从未调用，并确认焦点回到输入框。测试还覆盖 Escape 关闭、跨消息拒绝与工具行不可触发。组装 Web 回归在 Chromium 中对思考折叠行执行真实双击选词，并核对最终输入框草稿。

## Consequences

续问所需原文和用户草稿在同一条普通输入事务中合并，不新增消息类型或持久选区状态。原生文字选择手势仍遵循平台行为；长选区可能生成较长引用草稿，但发送前始终由用户检查和编辑。
