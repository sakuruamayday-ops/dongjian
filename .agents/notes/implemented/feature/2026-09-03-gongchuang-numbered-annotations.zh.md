# Agent Note: 对话编号注释

Status: implemented

[English](2026-09-03-gongchuang-numbered-annotations.md) | 中文

## 问题

把对话选文以 Markdown 插入草稿后，多段引文难以分别引用。引文重排或删除会使用户已经填写的编号失效，把历史命令引文当成新指令路由还可能重新启动无关专业任务。上游停靠栏移到输入卡片外后，文档附件和注释摘要也需要与输入框使用同一内容列尺寸。

## 决策

来源行预留窄编号列，在所属回复滚动期间保持可见，可见范围受该回复约束而非整个对话。不同次提交在同一回复使用相同编号时，编号附带提交序号。已存注释编号和引文保持不变。

产品向 Chat 提供可选的选文回调，并把不可变的编号引文保存到逐会话草稿状态。输入框显示数量入口，每项包含原始引文和可选的用户评论。移除和恢复草稿时，待发送条目从 1 连续编号，原消息标记同步；清空后从 1 重新开始。重排对象保留其发送准入身份，结算时消费已提交引文，保留之后编辑或重新添加的条目。共享展示组件也负责已发送消息、提交回显和待处理补充指令。非产品 Chat 继续使用[普通引用操作](2026-08-21-gongchuang-quote-selection-into-composer.zh.md)。

既有提示词准备流程把选文序列化为普通用户消息及其持久展示文本。展示投影分别呈现文件、注释和当前正文。草稿状态保存在逐会话浏览器键中；准入失败会保留草稿，准入成功只消费本次提交所含的对象标识。结算期间发生的后续编辑和新增会继续保留。Host 确认删除对话后会清除两种草稿存储。不新增事件类型、RPC、发布检查或后台任务。

Host 的意图投影只解析开头的注释元数据，并根据当前评论和正文分类。它不会把引文视为当前用户事实或授权。完整引文仍对模型可见，并可从 Session 日志重建。提供方、权限、签名技能、交付物及专业校验仍由原有模块负责。

文档和注释草稿栏共用输入框的最大宽度、两侧间距令牌和换行布局。文件激活继续使用既有系统应用桥接，不会启动新对话，也不嵌入预览器。

队列展示会先对完整展示文本调用产品准备流程提供的可选摘要投影，再进入队列普通预览截断。待处理提交回显使用同一投影。带独立展示投影的行不提供纯文本编辑内容，因为仅替换该文字会丢失模型上下文并保留过期展示元数据。移除和补充指令行为不变。

## 备选方案

**继续在草稿中使用 Markdown 引文。** 这种方式不能提供可独立移除的编号条目或紧凑摘要，并会混淆引文与用户的新请求。

**移除后保留编号空缺。** 用户需要连续编号，清空后从第一个编号开始。草稿编号遵循这一规则；已发送元数据、用户手写正文和评论原样保留，不猜测文本中的编号引用。

**新增 Session 事件或 RPC。** 既有用户消息内容、展示文本和提示词结算已经保留所需数据与生命周期，第二套传输会造成重复。

**嵌入文档预览。** 用户已经明确选择让文件卡通过系统应用打开。预览渲染和新的文件导航流程不在本次变更内。

## 验证

所属测试覆盖持久化、编号移除、异常元数据、发送失败、准入期间编辑、删除后的过期结算、文件与注释组合投影、选文回调、焦点及只读历史。组装后的浏览器覆盖原生文字选择、选择器与拖入入口、附件和注释布局、评论、刷新、仅注释发送及持久回放。操作系统导入与打开边界使用具名测试文件，不声称覆盖安装包或系统默认应用。Host 路由测试会根据明确评论和当前正文保留专业分类，同时排除历史引文。

## 结果

引文只在发送时增加 token，之后仍可分别查看。已有消息中的 Markdown 引文不会被静默迁移。草稿持久化仅限本机，不提供跨设备同步。元数据用于展示与路由，不是信任机制。正式安装包和发布证据在产品文档中另行记录。
