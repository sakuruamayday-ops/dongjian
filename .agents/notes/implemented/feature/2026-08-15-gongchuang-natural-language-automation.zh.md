# Agent Note：共创自动化自然语言时间设置

Status: implemented

[English](2026-08-15-gongchuang-natural-language-automation.md) | 中文

## 问题

原自动化编辑器只提供四个固定间隔，并用“保存后启用本机调度”描述启用动作。业务用户需要用日常中文表达常见执行时间，或自行选择自定义间隔；原技术文案也没有直接说明保存后的行为。

## 决策

自动化编辑器提供两种等价设置方式。“一句话设置”以确定性规则识别每天时间、星期和 5 分钟至 365 天的固定间隔，只把结果填入可复核表单，不直接保存。“手动选择”提供首次本地执行时间、现有预设周期和相同范围的自定义间隔。用户还可以在普通助手会话中要求创建计划；范围固定的模型工具会把当前 Session 唯一解析到一个企业空间，并且只能写入固定间隔任务。

保存始终需要用户明确操作。编辑器内启用任务使用“保存并启用”，由桌面本机调度器执行；停用任务使用“仅保存，暂不启用”。会话工具的每次调用都进入签名策略的 `ask` 名单，只有用户确认展示任务名称、周期和首次执行时间的卡片后才会持久化。电脑关机或休眠期间不会生成云端运行，客户端下次启动后处理已经到期的任务。

仅有确认要求仍不能阻止一个具体故障：模型可以绕过工具，直接在普通助手正文中伪造 `automation-*` 编号并宣称成功。类型检查、工具注册表、任务 ID 唯一约束和签名 `ask` 策略只能保护真实工具执行；没有调用时，这些机制无法观察或约束自然语言完成态。因此，本地自动化服务增加一条窄范围的同轮一致性检查：只检查“用户明确要求创建自动化任务，并且助手正面宣称已经创建或启用”的轮次。原生和代码模式调用分别保留自己的结果与已保存任务 ID，部分成功不能授权“全部已创建”的主张或虚构任务编号。如实说明部分结果、取消和失败仍可通过。每轮最多要求纠正一次；部分成功只要求如实解释，不会重新创建已保存任务或重试被拒绝的调用。该检查不扫描无关回答，也不冻结模型措辞。

确认卡既能解析原生工具调用，也能解析 code mode 的嵌套调用；它按桌面本地时区展示任务名称、周期和首次执行时间，并且只有明确点击创建按钮才发送 `allowed-once`。进入“自动化任务”页面会重新读取 Host 快照，使会话中成功创建的任务从新提交的注册表 revision 显示，而不是停留在页面启动时的旧快照。

首次运行必须是带时区的合法 ISO 日期时间。确认卡和任务列表按真实间隔派生周期，包括标签错误的旧记录。创建和更新会确认所选企业空间仍存在；正在运行的任务拒绝更换空间。现有删除操作会停用后续调度，只停止该任务拥有的排队消息或活动轮次，再删除任务及其回执，同时保留对话和文件。没有绑定的认领会在提示进入前取消。停止超时后任务保持停用且可重试，删除后的迟到回执不会复活任务。回执裁剪只淘汰已结束运行，保留活动认领令牌。

每个任务还拥有一个由手动和定时运行共用的持久结果会话。客户端会在提交提示前绑定首个专用 Session，将后续执行追加到该会话，必要时取消归档，并在助手界面打开当前执行。如果该会话已被明确删除、本地 Session 记录消失，或属于其他企业空间，当前认领会在任务企业空间创建替代会话，并以旧编号作为比较换入条件，同时更新任务和运行。这既避免已删会话或旧版跨空间绑定卡住调度，也不会移动旧历史或允许旧客户端覆盖较新绑定。签名策略若在分配轮次前移除已接纳消息，客户端会根据同一消息已离开队列、会话空闲且 Host 返回无轮次 agent 错误的状态结算失败，不再让运行一直保持到陈旧认领超时。

手动执行会在注册表修改队列和全页忙碌状态之外等待模型完成。只有当前任务显示运行中，用户仍可停用后续运行或管理其他任务。轮询失败会被捕获；后续成功轮询即使没有到期任务，也会清除它自己留下的陈旧错误，但不会清除无关操作错误。

固定专业人设要求面向中文用户时，可见进度、工具调用说明、简明思考摘要与最终答复优先使用中文。来源名、模型名、代码、技术标识和工具原始错误保持原样。该要求不要求展示隐藏的内部推理链。

## 备选方案

**没有范围固定的工具和确认流程，直接把助手正文当成已保存计划。** 不采用，因为正文既不是持久动作回执，也不构成用户授权。实际实现采用封闭参数结构、唯一企业空间解析和签名策略逐次确认，失败时保持关闭。

**只加强提示词，禁止模型伪造完成态。** 不采用，因为供应器行为可能漂移，提示词也没有持久动作回执。窄范围运行时检查只观察明确创建意图、完成态主张和缺少成功结果之间的精确不一致。

**只增加更多固定周期。** 不采用，因为仍然无法表达 90 分钟、2 天等常见业务间隔。

**开放 cron 表达式。** 不采用，因为它偏向开发者、普通用户难以校验，并且会暗示当前固定间隔调度器并未实现的日历语义。

## 结果

编辑器中的自然语言识别采用确定性规则，不会静默猜测不支持的表述；识别失败会显示可操作的校验信息，并保持任务未保存。会话创建只在人工确认的封闭结构工具调用前增加模型理解。调度器继续存储固定间隔和本地时间锚点，因此 V0.1 不声称支持 cron、节假日日历或云端执行。

被拒绝或失败的调用保持注册表 revision 不变，并允许模型正常说明。确认成功只推进一次持久 revision；进入自动化页面增加的是一次本地快照读取，不是云同步，也不会重复写入。

现有 V0.1 注册表以增量方式迁移，不提升结构版本。缺少新会话字段的任务会从已保留的运行回执中采用最新的非空 Session 编号；没有此类回执的任务在下次运行时完成绑定。若采用的 Session 属于任务原企业空间，首次运行会在当前企业空间原子替换该绑定。历史回执保持不变。
