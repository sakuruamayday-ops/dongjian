# Agent Note: Windows 关闭偏好与账号恢复

Status: implemented

[English](2026-08-24-windows-close-and-account-resume.md) | 中文

## 问题

Windows 用户无法选择点击标题栏关闭时是直接退出还是保留在托盘。另一方面，启动时可能在操作系统凭据恢复稳定之前投影未登录快照，导致已记住的用户每次启动都看似需要重新登录。

## 决策

Windows 保存三种本机关闭行为：询问、缩小到托盘或直接退出。首次关闭和旧版静默托盘偏好文件都会迁移为询问。询问模式下，Host 只发出一项渲染器请求，紧凑弹窗以无选中行框体的纵向单选列表展示托盘和退出，并提供记住、取消及确定操作。只有明确记住的响应才把托盘或退出原子写入 `desktop-preferences.json`；设置页用紧凑下拉框提供同样三项选择。直接退出继续通过 `app.quit()` 和现有运行时有序关停；macOS 保持菜单栏关闭行为。

账号启动调用串行化 Host 刷新，等待 Keychain 或 Credential Manager 恢复完成后再投影身份。记住密码默认开启但仍由用户控制。操作系统凭据库之外只持久化凭据引用和行为偏好。

## 曾考虑的替代方案

**所有平台强制关闭到托盘。**不采用，因为 Windows 用户明确需要直接关闭选项，两个操作系统的惯例也不同。

**在渲染器设置中缓存密码。**不采用，因为这会弱化现有凭据边界，也没有解决启动竞态。

## 后果

明确记住的 Windows 关闭行为可在重启后恢复，取消选择时窗口保持打开，直接退出仍保持有序。记住的身份只在凭据恢复稳定后投影。单元测试覆盖偏好迁移、持久化、请求响应关联、弹窗操作和刷新竞态；打包 Windows 对话框与托盘交互、真实 Keychain/Credential Manager 重启仍属于设备验收项。
