# Agent Note: 产品自有会话深链接

Status: implemented

[English](2026-08-31-product-session-deep-links.md) | 中文

## Problem

产品复制的是 `codex://threads/<session-id>`，但共创桌面应用既不持有也未注册该协议。这个地址暴露了另一个产品的身份，并且无法可靠地从冷启动或已运行的共创应用中重新打开会话。

## Decision

桌面应用持有并注册 `gongchuang://threads/<session-id>`。解析器只接受该固定 host 和一个长度受限的本机会话标识，拒绝凭据、查询参数、片段、多余路径和其他协议，并通过固定 IPC 通道把已校验标识发送给沙箱渲染器。

冷启动参数、macOS `open-url` 和第二实例参数共用同一解析器。主进程和 preload 会各自暂存一个标识，直到下游消费者就绪。客户端只打开本机会话列表中存在的会话；已归档会话会先恢复，已删除或未知会话会被拒绝。

## Alternatives considered

**保留 Codex 协议作为兼容别名。** 已拒绝，因为本应用从未持有该协议，继续公开它会保留产品身份泄漏。

**复制 HTTP 地址。** 已拒绝，因为会话只存在于当前设备，产品没有经过身份验证的公开会话路由。

**把绝对会话路径放进地址。** 已拒绝，因为这会暴露本机文件系统细节，并让协议超出应用实际需要的不透明标识。

## Consequences

复制的地址会标识共创，并通过安装包注册的桌面协议工作。它仍是当前设备引用，不是分享链接：其他设备或已删除会话无法解析。协议输入会在进入客户端导航前完成校验。
