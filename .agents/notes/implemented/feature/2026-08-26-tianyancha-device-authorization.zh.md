# Agent Note: 天眼查设备授权的 OAuth 令牌留在 Host

Status: implemented

[English](2026-08-26-tianyancha-device-authorization.md) | 中文

## Problem

产品原有天眼查连接器只接受手工粘贴的 `TYC_API_TOKEN`，而天眼查当前 AI 入口已把智能体客户端引向 OAuth 设备授权、官方 CLI 和场景技能。公开页面仍提供免费接入，但调用会消耗 MCP 与 CLI 共用的账号额度。直接删除会失去仍然可用的数据源；继续只提供 Key 会让新用户停留在旧路径，并诱使渲染器持有可续期令牌。

## Decision

`@gongchuang/connectors` 负责天眼查鉴权。它核对固定的受保护资源与授权服务器元数据，动态注册本机客户端，发起设备授权，并且只通过生成的 Remote 暴露官方授权地址、用户授权码和不透明事务标识。只有用户明确确认后才交换令牌。

访问令牌、刷新令牌和动态客户端元数据都保存在操作系统凭据服务。Host 会在访问令牌到期前一分钟内续期；续期或连接验证失败时恢复全部旧凭据；只有官方 MCP 至少返回一个工具后才显示就绪。手工粘贴 Key 仍作为兜底，并清除旧 OAuth 刷新状态。额度耗尽与身份失效使用不同的产品诊断码。

产品直接消费天眼查官方 MCP，不把官方 CLI 或独立场景技能仓库复制进已签名产品技能包。

令牌交换与刷新继续绑定到受支持的固定官方 Token 端点。发现流程若返回不同 Token 地址，会在注册前拒绝，而不是先接受再在后续请求中忽略。这保留现有端点限制，不增加任意端点路由，也不宣称线上服务已经更换地址。

客户端授权会等待更早的配置写入完成，但在用户浏览器批准期间不占用共享连接器修改队列。取消、Esc、关闭弹窗和离开页面都会终止准确的本地宿主事务，包括注册、回调等待、轮询、交换和凭据校验；事务 ID 在发现开始前就已确定。取消会等待归属任务静止并保留原凭据，部分回滚失败会给出可操作错误，并只禁用该连接器。迟到响应不能覆盖更新尝试。短暂待处理的设备轮询和丢失的取消确认都可明确重试；无关连接器和地区设置保持可用，旧宿主版本不能回退较新的设置。

## Alternatives considered

**删除天眼查。** 未采用，因为官方 AI 页面和已登录账号仍提供免费额度。准确限制是按额度使用，而不是已经没有免费接入。

**只保留 API Key 配置。** 未采用，因为它不再是官方推荐的智能体接入路径，也不能在无需用户反复替换的情况下提供可续期访问。

**把 OAuth 材料保存在渲染器状态或浏览器存储。** 未采用，因为访问令牌、刷新令牌和动态客户端密钥不得通过 Remote 进入浏览器控制的持久化面。

**内置 `tyc-cli` 和天眼查场景技能。** 未采用，因为当前消费方只需要远程 MCP；内置会复制独立更新的产品，并在没有当前用途的情况下扩大签名运行时。

## Verification

协调器测试覆盖官方元数据发现、动态注册、设备授权、未完成流程替换、令牌交换、续期和端点不一致拒绝。Host 集成测试覆盖 Bearer 连接、操作系统凭据写入、手工 Key 迁移、`tools/list`、额度诊断和续期回滚。客户端测试证明打开官方页面不会自动交换令牌，只有用户明确确认后才完成。确定性取消屏障覆盖注册、回调等待、迟到令牌响应和暂停的凭据写入，包括部分恢复失败。控制器与弹窗测试覆盖显式重试、取消确认丢失、无关写入、Esc 和迟到结算，且不会干扰后来打开的弹窗。

## Consequences

天眼查登录改用其持续维护的官方路径，可续期密钥仍由 Host 持有；必要时用户仍可粘贴 Key。连接器依赖天眼查授权服务和账号额度，完成浏览器登录仍需用户操作。重新发起授权会替换 Host 中上一笔未完成事务，因此关闭弹窗不会造成本地锁死；天眼查仍可能按其自身生命周期策略保留已放弃的动态客户端注册。
