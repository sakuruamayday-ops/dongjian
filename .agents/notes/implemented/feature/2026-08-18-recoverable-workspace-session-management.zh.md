# Agent Note：可恢复的企业空间与会话管理

状态：已实现

[English](2026-08-18-recoverable-workspace-session-management.md) | 中文

## 问题

会话存储的 cwd 不可变，只有当该 cwd 解析后等于企业空间的规范路径时，Workspace 才允许附加会话。重新归属既有会话要么改写持久身份，要么生成必然被 Workspace 拒绝的成员记录。企业空间和会话移除还需要可恢复的可见性状态，确保产品操作绝不删除企业目录、用户文件或持久化日志。

## 决策

企业空间和会话的归档与删除是两种独立、可恢复的可见性状态。Workspace 领域持久化四组互相约束的 id：已归档和软删除的企业空间，以及已归档和软删除的会话。软删除绝不会移除 Workspace 记录、企业目录、用户文件、Workspace 会话归属或持久化会话日志。

Host 通过 `workspace.list`、各项管理一元方法和 `host/workspace-management-changed` 提供完整管理快照。客户端运行时分别投影活动、已归档和已删除的企业空间；隐藏已归档或已删除会话，但不移除其列表与日志数据。`listArchived`、取消归档与恢复回调为设置页提供真实恢复路径，而不是只做视觉页面。

将会话移动到另一企业空间是一项可恢复的复制操作。`session.fork` 接受可选的目标 `workspaceId`；活动目标会让子会话使用其规范路径，源会话 header 保持不变。子会话保留已完成的种子历史、日志中最新的模型选择、标题事件和 `parentSession` 谱系。未知、已归档或已软删除的目标，以及运行中的源会话，都会在发布子会话前失败。

`WorkspaceRuntime.moveSessionToWorkspace` 对已经归属于目标的会话直接返回源 id。其他情况先向目标 fork，仅在 Host 确认目标附加成功后归档源会话。fork 或附加失败时源会话保持活动；归档失败时已附加的子会话与源会话都保持活动，恢复路径不依赖重建已删除数据。

既有 `workspace.delete` 继续作为明确的解除注册操作，供现有调用方使用。产品界面的删除动作使用 `deleteWorkspace` 和 `deleteSession`，不会调用解除注册操作，也不会触碰源文件。

## 已考虑的替代方案

**改写既有会话 cwd。** 不采用，因为 cwd 是回放、工具运行和 Workspace 校验依赖的持久创建身份；改写后历史执行上下文会产生歧义。

**把既有会话直接附加到目标 Workspace。** 不采用，因为 Workspace 应当拒绝规范 cwd 不一致；绕过该检查会破坏分组语义。

**先归档源会话，再创建子会话。** 不采用，因为 fork 或附加失败会隐藏唯一可用的会话。源会话归档必须作为最终提交点。

**永久删除已归档或已移动记录。** 不采用，因为产品要求可恢复，并且必须保留企业文件和会话日志。

## 影响

移动会生成新的 Session id 和明确谱系，不保留对象身份。目标附加失败可能留下已发布但未分组的子会话，源归档失败则会留下两个活动会话；两种结果都保留全部数据并可被对账，而不会隐藏源会话。运行中的会话必须先完成或停止，移动才能捕获其全部已完成历史。

- Workspace 领域持久化与重启兼容默认值，包括归档和删除互斥。
- Host schema、目标感知 fork、源 cwd 不变、谱系、非活动目标拒绝、运行中源拒绝，以及附加失败报告。
- 客户端 manager/runtime 投影、目标 cwd 对账、同一 Workspace 无操作、源归档顺序、陈旧基线保护、当前会话清理与恢复回调。
