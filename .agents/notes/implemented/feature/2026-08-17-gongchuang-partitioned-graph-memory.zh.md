# Agent Note: 共创分区图记忆

Status: implemented

[English](2026-08-17-gongchuang-partitioned-graph-memory.md) | 中文

## 问题

普通会话与专业会话都需要复用稳定方法、用户纠正和任务上下文，但客户端不能因此变成只能处理专业任务的助手，也不能让不同企业的内容相互串用。云端记忆服务会增加账号侧数据存储和网络依赖；所有会话共用一个本地图，则可能在一个企业空间中召回另一家企业的历史。

## 决策

桌面组合挂载 `@gongchuang/graph-memory`，其核心改编自采用 MIT License 的 Graph Memory Community Core。本机保存一套个人 SQLite 图，并为每个企业 Workspace 保存相互独立的图。每次提取、召回、检索和记录都根据当前 Session 解析分区；模型与渲染器都不能提供数据库路径或企业标识。

已完成的用户和助手消息由该 Session 当前选中的模型异步提取。只有用户启用相应设置后，工具结果才参与提取。提取与图维护不会阻断可见回复；检索使用 Node 内置 SQLite FTS5，不需要 Embedding 凭据或独立服务。

相关历史通过 `system-prompt/assemble` 以有上限、随请求变化的后缀进入上下文，并明确标注为不可信参考。它不能覆盖当前指令、证明现行政策或企业事实，也不能给普通会话新增专业限制。模型还会获得四个按当前分区工作的中文记忆工具，分别用于查看状态、检索、记录和统计。

设置页可以立即关闭提取与召回、控制工具结果是否参与、查看汇总计数，并清空全部本地图数据。清空操作会等待正在执行的提取结束，且不会删除原会话或企业文件。渲染器只能获得偏好和计数，不能读取图内容或数据库路径。

## 备选方案

**使用上游 Pro 界面。**不采用，因为 1.6.0-beta.1 说明 Community 核心可用，但面向 DSH 的 Pro 管理界面尚未交付。客户端只实现 Host 服务真实支持的控制项。

**把 Graph Memory 作为 MCP 服务运行。**不作为内置默认方案，因为本机数据已经具有 Cordis Session 与 Workspace 身份，再增加一个进程会带来额外的连接生命周期。用户仍可在通用 MCP 页面添加独立的记忆 MCP。

**所有会话共用一个数据库。**不采用，因为不同企业的隔离将完全依赖查询过滤。分文件存储让企业隔离不依赖模型行为或检索措辞。

**强制使用 Embedding。**不采用，因为 FTS5 无需额外模型、凭据、下载或随包运行时即可提供有效的本地默认检索。Embedding 支持保持可选，产品组合不启用。

## 结果

普通会话和专业流程都可使用长期记忆，同时不改变 Agent Loop 或专业模板默认值。用户纠正可以在后续复用，但当前指令和新核验的证据始终优先。V0.1 的本地图不会跨设备同步，设置页也不能逐条编辑节点或关系。定向的包测试、Remote 控制器测试、真实服务组合测试和企业隔离测试覆盖当前操作；macOS 与 Windows 打包后运行仍纳入安装包验收。
