# Agent Note: 原生选区与已保存连接恢复

Status: proposed

[English](2026-09-03-native-selection-and-connection-recovery.md) | 中文

## 问题

原生整段选择可能把后续操作栏一并纳入，导致本来可以引用的助手段落不再出现注释动作。替换 API 密钥被拒绝时，宿主仍保留原凭据，但渲染器会清除“已配置”状态，隐藏使用已存密钥恢复的入口。重新打开已保存的自定义连接还会丢失可编辑端点字段。

## 方案

把选中文字裁切到消息操作栏和来源注释控件之前。如果原生选区结束在后续非正文行的前导图标中，且没有选中该行文字，也回退到正文末端。替换失败、刷新和快照请求期间保留已知连接配置。现有脱敏连接快照只返回通过验证的可编辑端点字段，不返回密钥或凭据引用；重开表单从这些字段初始化，密钥输入始终为空。

源码修复已有定向回归覆盖。候选包的原生复测仍待完成，本记录不代表正式发布。

## 备选方案

关闭整段选择会移除预期交互。把替换失败的连接视为未配置，与宿主保留凭据的事实矛盾。返回原始设置填充表单会暴露凭据引用，并可能泄漏旧网址中的秘密。

## 验收标准

原生整段选择应提供只包含正文的注释。替换密钥被拒绝后，使用已存密钥恢复的入口仍可用。重新打开自定义和可编辑托管连接时，地址与模型 ID 保持不变，密钥输入为空。合法密钥替换在进程重启和后续真实调用后仍有效。连接传输失败会显示并结束，而不是一直处于加载状态。

## 风险

这些仍是等待原生候选验证的源码改动。现有签名、发布、凭据回滚和提供方探测要求保持不变。
