# Agent Note: 部分轮次历史中的交付文件

Status: proposed

[English](2026-09-04-tail-page-deliverables.md) | 中文

## Problem

B20 原生客户端重新打开合成会话 `session-8c943363-beb6-4bd1-882f-d80e559a4d12` 后没有文件卡片。加载前一页历史后，待完善文件卡恢复，点击可在 WPS 打开对应 DOCX。已加载的持久化尾页包含成功的文件检查和宿主的草稿文件映射，但交付文件定义需要等分页补齐 `turn/start` 后才发布轮次数据。

## Proposal

保留既有定义、轮次身份和事件归约函数。当引擎尚未取得开始状态时，使用同一归约函数，仅从当前上下文已加载的匹配事件推导交付内容。完整的 PTC 文件发布或宿主质量通知可独立成立；根工具结果需要其已加载的调用参数。禁止扫描其他上下文、从模型正文猜测路径、自动加载整个对话或伪造开始事件。完整轮次保持原有增量更新路径。

此实现沿用[对话组装](../../../../docs/subsystems/conversation.zh.md)的现有回退规则，不替代其[职责划分决定](../../implemented/architecture/2026-08-09-client-conversation-node-assembly.zh.md)。

## Alternatives considered

**渲染前加载完整轮次。** 这会让已发布文件的访问依赖额外历史请求，并隐藏当前页已有的完整终态回执。

**合成开始事件或从模型正文猜测路径。** 两者都不能形成可信的发布证据，也会混淆既有事件职责和回放语义。

## Acceptance criteria

原生复现和定向测试覆盖缺失轮次开始、待完善文件替换、多份 PTC 文件、仅文字草稿、失败及孤立结果、不可信元数据和轮次隔离。补入真实开始事件后必须保持去重及最新分类。需完成包级与装配客户端测试，并在新打包的原生客户端复验；此变更不证明报告内容合格，也不重置模型校验次数。

## Risks

回退只能重建已加载上下文中的完整事实。缺少调用参数的根工具结果仍不能形成文件卡。待开始的上下文更新时重放自身匹配事件，已开始的上下文保持普通增量归约。文件可打开不等于专业内容已通过。
