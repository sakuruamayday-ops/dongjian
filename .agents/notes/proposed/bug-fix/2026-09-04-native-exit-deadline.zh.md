# Agent Note: 钥匙串等待后的 macOS 原生退出时限

Status: proposed

[English](2026-09-04-native-exit-deadline.md) | 中文

## 问题

已安装的 ARM 候选包在 9 月 4 日 01:07:48 完成运行时清理，但主进程仍存活。一分钟后的原生采样显示有线程等待 `SecItemCopyMatching` 和钥匙串解密。Electron 原生退出阶段已经停止派发原有 JavaScript 超时；辅助进程均已退出，运行时清理完成不等于进程退出完成。

## 方案

保留现有十秒持久化清理时限和十二秒绝对退出时限。在 macOS 开始退出时，通过已内嵌的 Koffi 调用 `alarm(12)`，同时保留 JavaScript 兜底。系统闹钟不依赖 JavaScript 事件循环，并随本进程消失，不会向复用的 PID 发送信号。正常关闭仍走 Electron 退出并先于闹钟完成。该机制不在正常使用时启动，也不绕过钥匙串同意。

## 备选方案

**只依赖 JavaScript 定时器。** 原生钥匙串调用阻塞时，事件循环可能无法派发该定时器。

**钥匙串不可用时立即终止。** 这会跳过正常的持久化运行时释放，并可能丢失待写入状态。

## 验收标准

独立进程启动真实系统时限后阻塞 JavaScript 二十秒，必须由 `SIGALRM` 终止，而不是由 JavaScript 回调或测试的后续清理结束。既有正常清理、超时、系统信号和窗口生命周期用例保持覆盖。重建的签名 App 仍须在真实钥匙串授权不可用时验证退出；源码测试不能单独证明原生验收通过。

## 风险

原生闹钟作用于整个进程，必须只在退出阶段启用、随进程结束失效，并给正常关闭路径留下足够完成时间。
