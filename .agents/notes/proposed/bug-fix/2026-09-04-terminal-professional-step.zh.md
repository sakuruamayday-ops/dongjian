# Agent Note: 专业校验进入终止态后停止模型步骤

Status: proposed

[English](2026-09-04-terminal-professional-step.md) | 中文

## 问题

原生合成会话 `session-288bc507-8b6a-486a-86c7-2775c30a93f7` 在第 27 步收到 `repairable`、第 28 步收到 `draft` 后，仍继续运行到第 45 步。校验器持续返回冻结的待完善结果，但模型忽略停止说明，改用其他工具并继续尝试证据绑定。模型持续请求工具期间，现有轮次停止监听器没有执行机会。

## 方案

在终止态待完善或失败后，使用现有 `pre-step` 决策拒绝下一次请求。完成本次工具交换后，持久保存宿主拥有的问题通知，其中包含无文件诊断和“结果尚不能正式使用”的说明。保留原始文件及现有的显式用户修订路径，不增加新的契约、计数器、生命周期控制器或发布例外。

终止结果后的取消操作保留其阶段。恢复带有待完善或失败结果的旧暂停检查点时，把显式继续视为新的用户修订。普通轮次只加载共享读取器的协调器或路由器，不应激活专业依赖：B07 已正确读取 PDF 两页，却又多花三步激活业务依赖并校验转录。具体专业技能和真实业务请求仍继续触发现有检查。

B08 的普通读取器验收仍失败，因为真实客户端会把文档读取说明附加到用户消息。路由在第一次模型请求前就匹配到了产品上下文中的业务词。宿主应使用现有 `source.displayText` 投影判断意图，排除附件行和注释引文，同时保留当前评论。Loader 回归使用捕获的真实原生用户消息及其展示投影，而不是简化的手写输入；其他投影测试覆盖带业务名称的附件。

## 备选方案

**依赖模型遵守终止工具消息。** 捕获的会话在终止结果后又运行了 17 步，说明仅靠文字不能结束轮次。

**持续重试校验直到通过。** 这会重新引入无界修复循环，并在没有新用户修订时继续消耗工具或 token。

## 验收标准

定向测试覆盖 `repairable` 后仍允许一次修复、对话和文件终止态拒绝后续步骤、无文件诊断去重，以及后续显式修订。真实 Loader 组合覆盖 PTC 执行。原生验收必须看到第二次校验失败后进入空闲、诊断可见且不会自动发起第三次校验；源码测试不能代替该 UI 结果。

## 当前实现

`repairable` 只打开一个模型步骤。该步骤可以重读被校验器拒绝的同一候选文件并在现有 `run_code` 中修改、重新校验；不得重新列目录、搜索资料、加载技能或读取无关文件。若这一模型步骤没有提交第二次校验，下一步直接进入待完善终态，不再让模型继续探索。对话模式传入 `candidateArtifactPath` 时也保留该精确候选路径；修复用尽后，宿主发布带“待完善”标记的候选文件卡和问题清单，不把它伪装成正式交付物。

数值证据检查同时修正了同类误判：带千位分隔符的数值按一个整体绑定，PDF 抽取产生的页码、整改路线时间坐标和周转天数公式中的 `×365` 不作为客户事实；独立金额、指标或独立出现的 `365` 仍必须绑定证据。专业工具说明要求逐项绑定全部派生数值，不再允许只提交“代表性”计算。

51 项签名技能的共享便携执行说明同步要求：隐藏工具只能在 `run_code` 内以 `await tools.<name>(...)` 调用；不得为了理解用法预读脚本、模板、示例或测试，只有真实命令失败且接口仍有歧义时才读取直接相关源码。这一修改只减少无意义工具步骤，不改变技能业务要求、签名校验或专业终态。

截至 2026-09-05，策略定向回归 155 项和产品版本定向回归 325 项通过；V1.6.18 候选包 13/13 发布前检查、51/51 签名、隔离安装及技能主仓 380 项通过、4 项跳过。全仓第一次回归发现产品 UI 仍显示 `1.6.17`，已修正为 `1.6.18`；修正后全仓 1199 个文件、19484 项通过，另有 9 个文件和 118 项跳过；GUI 331 个文件、4423 项通过、1 项跳过；构建后 Web 回放 96 个文件、334 项通过，另有 1 个文件和 7 项跳过。重新打包与安装客户端原生复验仍需完成，因此本 Note 维持 `proposed`，不得据此宣称已发布。

## 成功文件校验

B18 目录会话 `session-8c943363-beb6-4bd1-882f-d80e559a4d12` 已通过文件预检，却在尚缺其他回执时宣称交付完成。持久工具卡片中包含仅适用于对话模式的“以候选正文结束”说明。PTC 不会把卡片正文转发给模型，而是返回结构化值；其 `formal` 状态没有给出下一步。共享工具说明和搜索预算通知也没有区分文件预检与对话完成。这条记录只能证明指引错误且不完整，不能证明模型看过卡片文字。

工具应在现有结构化结果中返回与模式对应的 `nextStep`，卡片也从同一字段渲染。对话模式成功时保留准确终稿文字；Office 和 PDF 预检后继续生成并做文件校验；文件模式成功后继续现有文件检查。失败和待完善结果继续保持一次修复上限与终止行为。不合成回执、不移除校验，也不改变循环或 PTC 模式。

真实 Loader 测试覆盖四种成功模式，并断言返回的 PTC 值与持久工具文字一致，同时固定其说明快照。测试还复现原生过早预检序列：专业绑定前的探测成功不能满足已绑定交付所需的可打开回执。既有拒绝用例继续覆盖过早发布和终止态停止。已安装客户端仍须对原生目录失败做验收；源码测试不能证明模型已经遵循新说明。

## 风险

过早拒绝下一次请求可能压掉合法的 `repairable` 修复或显式用户修订。因此阶段判断必须区分可修复状态与终止状态，并保留现有的用户控制修订路径。
