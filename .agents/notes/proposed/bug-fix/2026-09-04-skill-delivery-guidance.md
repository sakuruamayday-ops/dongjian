# Agent Note: Skill Delivery Guidance From Native QA

Status: proposed

English | [中文](2026-09-04-skill-delivery-guidance.zh.md)

## Problem

The B09 enterprise-profile task completed after 28 steps, including a guessed delivery profile owned by a different skill. The existing activation notice listed profile IDs only when a skill owned one; silence left the model to search registries and guess. The B09 evolution-governance task interpreted a ban on releasing the candidate as a ban on showing the requested local file card. Its supplied facts also became stronger claims about missing approval records.

## Proposal

The existing activation notice states explicitly when a registered skill owns no signed delivery profile and must omit `deliveryProfileId`. The local-file tool description separates a conversation file card from uploads and software or skill releases. Neither change alters validation, authorization, signing or publication behavior. The skill candidate separately distinguishes a user's explicit absence statement from an unprovided document and preserves a partial script-test result as partial evidence.

The desktop projection makes the Host-native `gongchuang_render_pdf` tool the only PDF renderer when that tool is available. It overrides standalone skill renderer commands that require an unpacked Playwright installation, and it requires an explicit `timeoutMs` for other commands that can remain resident. This keeps PDF creation inside the packaged application and prevents a missing development dependency from turning into an unbounded browser process.

The rewrite checker uses ASCII word boundaries for Latin identifiers. Python Unicode word boundaries treat adjoining Chinese as part of the same word, so `整机X1` could be missed and a formatting-only space could create a false difference. Regressions include changed models, changed acronyms, Chinese spacing and embedded lowercase identifiers.

## Alternatives considered

**Let each skill infer delivery status and evidence semantics independently.** This reproduced conflicting instructions, guessed profiles, and stronger claims than the supplied facts support.

**Remove professional validation from business tasks.** This would discard evidence, calculation, and formal-file checks instead of fixing their bounded guidance and terminal behavior.

## Risks

Narrow intent clauses can under-match real professional work if their exclusions become broader than the captured user request. The candidate therefore retains direct policy, formal artifact, evidence, quantity, and affirmative eligibility checks, and requires final native business-flow acceptance before release.
